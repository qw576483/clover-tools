# `shim/EngineShim.cs` —— 引擎门面替身（写之前先读这一页）

## 它是什么

一个**手写的**引擎替身：只声明「被编译进来的项目源码真正用到的引擎成员」（类型 / 方法 / 属性 / 常量），
签名逐条对齐真实引擎。它**不是**引擎本体，**不参与打包**，只为了在离线宿主里把项目源码编过 + 跑断言。

## 为什么需要它（而不是直接引用引擎 DLL）

1. **跨仓库 / 引擎在改**：引擎 DLL 往往比源码旧（或本地根本没编）⇒ 引用它会得到
   「调新 API 报 CS0117/CS1061（误判成自己写错了）」或「拿旧 DLL 编过已被删掉的 API（假通过）」。
2. **替身自带覆盖率告警**：真实引擎一旦改签名，宿主**编译报错**。
   这正是它存在的意义 —— 它不是"随便糊一个能过就行"，而是**引擎契约的一份可编译副本**。

## 怎么写（三条硬规则）

1. **只写源码真的用到的那几个成员**，一个不多。多写 = 造出一个假的宽接口，宿主以后再也发现不了真实缺口。
2. **每个成员上方注明出处**（真实引擎里的文件路径 + 成员名）。改签名时靠这些注释才能定位。
3. **跨宿主复用同一份文件**（例如 `..\<其它宿主>\shim\EngineShim.cs`），
   ⛔ 不要每个宿主各抄一份 —— 抄 N 份就是 N 处漂移点。
   一个文件在同一 csproj 里只能 `Compile Include` 一次（两次 ⇒ CS2002）。

## 典型内容（按需，不是清单）

- 日志门面（如 `ILogger` 接口 / `Game.Logger.Info|Warn|Error`）—— 项目源码里到处都在打日志，
  所以几乎每个宿主都要它；替身应把日志行**留在内存里**，断言才能数「这一站恰好一条日志」。
- 纯逻辑工具（随机数 `Rng`、等距几何 `IsoLayout`、`Dir8`、`AStar`、`LogThrottle`）：
  ⚠️ 这些**优先链真实引擎源码文件**（`<Compile Include="$(CloverEngineRuntimeDir)\Core\Rng.cs" />`），
  只有"链进来会拖一大串依赖"的才用替身 —— 替身是补丁，不是默认手段。
- `UnityEngine` 类型（`Vector2Int` / `Time` / `Shader` …）：宿主已经 `Reference` 了真实托管 DLL，
  **只在 DLL 里没有**（如只有编辑期才有的成员）才在替身里补，并在注释里写清原因。

## 与 `.csproj` 的接法

```xml
<Compile Include="shim\EngineShim.cs" />
```

若替身放在别的宿主目录下，就写相对路径 `..\flowcheck\shim\EngineShim.cs`；
`NoWarn` 里带上 `CS0436`（替身里重新声明的类型与参考程序集同名时，源码优先 —— 刻意的）。
