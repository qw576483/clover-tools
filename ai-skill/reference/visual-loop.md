# 视觉闭环（visual oracle loop）：把"看起来像"换成"一个数字 + 一份待办"

> **这是"能不能 1:1"的最后一块拼图。** 光有闸门只能**拦住**不像的东西；
> 还必须把**差异本身**变成**可执行待办**喂回执行者，让它能**迭代到没有差异**。
>
> 出处：PixelPilot（`github.com/overseek944/pixelpilot`，"Visual-oracle engine for pixel-perfect UI migration"），
> 以及围绕它的实践（Figma 像素级还原、设计稿转代码的 diff 闭环，宣称可达 99.8% 像素匹配）。

## 一、核心思想（原文最重要的一句）

> **"像素级完美是渲染输出的属性，不是源码的属性。"**
> 所以 **diff 必须是目标函数**；执行者最小化的是"**测量出来的误差**"，而不是靠抽象猜测。

配套结论（同源，直接解释我们为什么卡在"差不多"）：
> **"没有视觉 ground truth 和反馈信号的转译，会卡在 ~80–90%；
> 最后那 10%（行高、亚像素间距、2px 内边距漂移）只存在于渲染结果里。"**

⇒ **所以："像不像"不能靠人眼眼看、也不能靠模型看，要靠 diff 数字 + delta 清单。**

## 二、闭环形状

```
采集基线(ground truth) ──► 实现/改代码 ──► 渲染 ──► diff ──► 达标?
      ▲                                                       │ 否
      └────────── 把精确 delta 清单喂回执行者 ◄────────────────┘
```

**基线怎么来**（必须可重复拍摄，否则噪声当回归）：
- 渲染**参考物那一侧**并保存：**截图 PNG + 解析后的布局/几何数据**（后者让"不一样"变成"改哪里"）。
- 确定性保障：**固定分辨率与缩放**、**冻结动画**、**等待字体就绪**、固定渲染模式/DPI。
- 覆盖矩阵：每个关键状态各自一条基线（菜单 / HUD / 交战 / 结算 / 死亡观战 / 暗态）。

## 三、判定：三个信号**同时**满足才算过

| 信号 | 机制 | 作用 |
|---|---|---|
| **像素 diff** | `pixelmatch`（**`includeAA: false`** —— 不计抗锯齿差异，UI diff 最重要的设置）；输出差异叠加图 | 量化像素漂移 |
| **结构相似** | `SSIM` | 抓"位移"这类原始像素比会低估的漂移 |
| **几何/布局 diff** | 按元素比 **包围盒 + 关键属性**（位置/尺寸/颜色/字号） | **把"不一样"变成"改哪里"** |

参考容差（PixelPilot 默认）：`maxDiffRatio ≤ 0.001`（≤0.1% 像素）、`minSsim ≥ 0.99`、`pixelmatchThreshold 0.1`。

## 四、输出必须是"待办清单"，不是分数

```
[OFF] 场景__分辨率__状态    diff=0.333%   ssim=0.9845
- 元素A: 尺寸 0,-4px; 上内边距 10px（应为 12px）; 圆角 6px（应为 8px）
- 元素B: 位置 x+2px; 字号 13px（应为 12px）
```

**这张清单才是喂给执行者的东西** —— 它把"再改改"变成"改这三个数"。
（可选加强：把 diff 叠加图也一并给模型看；但**判定仍然是 diff 数字，不是模型的观感**。）

## 五、怎么挂到 agent 上（三个通道，按需组合）

> **⛔ 先读这条（与 `SKILL.md` §1.13 的四拍对齐）**：**diff 是"贵动作"，只在批次边界跑，不许每次编辑都跑。**
> 截一帧 / 渲染一次 / 跑一次 diff 都是**分钟级**；**改一处就跑一次 diff = 把最贵的动作重复 N 次**。
> 正确节奏：**② 批量改完 → ③ 预演（跑 diff，拿 delta 清单）→ 批量修 → 再跑一轮**。

| 通道 | 挂点 | 做法 |
|---|---|---|
| **A. 钩子（首选）** | **批次边界**（③ 拍开始时） | 跑**一次** diff，把 **delta 清单注入上下文**让执行者**批量修**。⛔ 不做"每次保存即 diff" |
| | `Stop` | diff 超容差 ⇒ **拒绝结束**（必须带防死循环标记，见下） |
| **B. 工具（可选）** | MCP / CLI | 把 `capture_baseline` / `visual_diff` 做成工具，让执行者在**批次边界**自己调 |
| **C. 守护进程（可选）** | 会话外 | 监视文件变更 ⇒ **攒到"一次批次结束"再重 diff**；漂移时派发一次**限定范围**的新 run（默认只提示，不自动改） |

**防死循环（原文强调）**：`Stop` 钩子必须带"本轮已拦过"的标记（如 `stop_hook_active` / 标记文件），
否则会被反复拒绝结束而空转。

## 六、必须承认的边界（**诚实目标 = 感知容差内，不是字节一致**）

原文明确指出：**跨渲染引擎做到字节一致，物理上不可能**
（web → 原生、以及同理：**GoldSrc → Unity**）。诚实的目标是**"感知上落在容差内"**。

⇒ 所以"1:1"的正确判据分两种：

| 对象 | 判据 | 能不能到 |
|---|---|---|
| **数据/数值/公式/UI 坐标** | `diff = 0`（数值层面） | **能到 1:1** |
| **渲染画面（跨引擎）** | 三信号落在**容差内**；要"字节一致"必须先复刻对方的渲染管线 | 容差内可达；字节一致需复刻渲染管线 |

## 七、和本项目（Unity）对应起来

- 基线：**跑原版截同机位帧**，或用原版资源 + 固定相机位姿渲染一帧（相机位姿要写进基线记录）。
- 采集我们的：**固定分辨率 / 固定渲染模式 / 冻结动画**后截图（同机位、同画幅）。
- 判定：**像素 diff + SSIM + 几何 diff**；几何 diff 直接用我们已经有的坐标/包围盒数据（对应"布局树"那一列）。
- 输出：delta 清单（"这把枪的 viewmodel 位置 y+3px""这个面板圆角差 2px""准星粗细差 1px"）。
- 迭代：改 → 再渲染 → 再 diff，直到容差内或明确登记为"渲染管线差异，不可消除"。
  **（按批次：一轮「③ 预演」跑一次 diff 并批量修，见 §五 A 通道 —— ⛔ 不是"改一处跑一次 diff"）**

## 八、联络图（contact sheet）：把 N 个证据点压进 1 张图

> **为什么**：**AI 读图按像素烧 token**。「N 项 ⇒ N 张图、逐张读」比「N 项 ⇒ 2~3 张联络图」贵**一个量级**；
> 而**判定该由脚本做**，AI 只分诊。**截图是诊断工具，不是每格的常规证据**（`SKILL.md` §2 硬性判定第 3 条）。

### 8.1 采集前先出「证据分格表」

| 格号 | 状态 / 项 | **类别** | 判据（期望值） |
|---|---|---|---|
| 01 | 1-1 方块组位置 | `数值类` | 实体转储 `MysteryBox@T(2,0)` … |
| 02 | 星砖顶出 | `表现类` | ★ 真的从砖里弹出来 |
| … | | | |

**类别只有两种**：
- `数值类` ⇒ 判据是**日志 / 断言**，通常**不必进图**（进了也只是顺手带一格）；
- `表现类` ⇒ **必须进图**，且**格号要在索引表里对得上验收表的行号**。

### 8.2 采集（**一次跑完，不逐项进出 Play**）

两种形态按需选：
- **能同框就同框**：把同一时刻的多个对象**一次拉远框进画面**（零拼接、最省）；
- **互斥状态分帧采**：活着 / 死亡 / 通关这类物理上不可能同屏 ⇒ **逐帧截取所需的小区域**
  （`ScreenCapture.CaptureScreenshotAsTexture()` + `ReadPixels(rect)`，或宿主的截图命令），再拼版。
  **「一个画面放不下就切」的正确形态是切帧，不是切场景。**

### 8.3 拼版 + 烧标注（**用代码做，别手摆**）

用 `Pillow` 之类把各格拼成大图，**每格必须烧上**：`格号 + 状态名 + 类别 + 关键数值`。
- 格间留分隔线；角落放采集时间 / 构建标识；
- 同时输出 `index.tsv`：`格号 ↔ 验收表行号 ↔ 截图来源 ↔ 采集时的日志行`。

### 8.4 判定（**脚本按格做，AI 只看汇总**）

1. 脚本按格做**确定性 diff / 数值断言** → 逐格 `PASS / FAIL`；
2. **AI 只读整张联络图一次**（聚类 / 摘要 / 滤渲染噪声）；
3. 只有 `FAIL` 的格，才去看那一格的**原始大图**；
4. 终审仍然是人（§1.12 第 7 条）。

### 8.5 红线（不许借"整合"偷懒）

- ⛔ **时间序列 / 手感 / 动画节奏 / 音效时机**不许用拼版代替 —— 这类只能逐帧比或由人给基线（§1.12 第 7 条）；
- ⛔ **每格必须来自真实运行**：格上烧的数值与 `index.tsv` 里的日志行必须对得上，
  脚本要校验"这 N 条日志都在"（防止"拼一张图看起来都验了"）；
- ⛔ **检测不许变成 AI 看图**：判定永远是脚本数字，AI 只看汇总 ——
  否则就是把**最贵、最不可靠**的东西放到了判定位上（§1.12 第 1 条）。
