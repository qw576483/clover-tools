# 快校验环路：把「编译通过」的成本从十几分钟压到几十秒

> 出处：一轮真实项目复盘的**最贵一条**。原文结论一句话——
> **先让"验证"变便宜，再让"实现"变快。**
> 那一轮大半时间不是花在写代码上，而是花在"**每次验证要等 10~15 分钟**"上。

## 0. 为什么必须建它

Unity 首次导入几百~上千张贴图可能要**十几分钟**；`unity run` 一次往返同一量级。
在这种环路下**改一个编译错误要十几分钟才能确认** —— 一天试不了几次，人也就不敢改了。

**做法**：用 .NET SDK 的 Roslyn，把「引擎 Runtime 源码 + 业务源码」直接编译到
**Unity 自己的托管 DLL** 上，得到一个**几十秒**的编译校验环路；**Unity 只在最后确认一次**。

```bash
dotnet build -t:Rebuild      # csproj 里 <Reference> 指向 <Unity>/Editor/Data/Managed/**/*.dll + 包 DLL
```

> 定位：它是**类型层的快速校验**，不是替代 Unity。跑通它之后仍然要进 Play 做端到端（见 §2）。

## 1. 这个环路自己也会骗你 —— 三个已踩的坑（每个都能让你"以为过了"）

| # | 坑 | 后果 | 规矩 |
|---|---|---|---|
| 1 | MSBuild 里 `$(...)` 是**属性引用**，不是函数调用 | `$(Join-Path $Root 'Assets\**\*.cs')` 会被当成一个属性名 → 展开成**空字符串** ⇒ `Compile Include` 为空 ⇒ **一个业务文件都没编译**，报出来的错全是第三方包的 ⇒ 你会得出"我的代码零错误" | ① **路径在 PowerShell 里先展开**，csproj 里写死字面路径；② **自查覆盖率**：抽查几个关键文件是否真的进了 csc 命令行；③ **看产物**：编译成功必须真的产出 `.dll` |
| 2 | `dotnet build` 是**增量**的 | 第二次跑且无改动时 MSBuild **什么都不输出** —— 很容易被读成"零错误" | 一律 `dotnet build -t:Rebuild`，或先删 `bin/ obj/` |
| 3 | 第三方包源码的编译噪音会**淹没**自己的错误 | ugui 以**源码**形式存在（磁盘上没有 `UnityEngine.UI.dll`），直接编它的源码会冒出 110 个错（`UGUIHelpURL` 是 Unity DLL 的 `internal` 成员，靠 `InternalsVisibleTo` 才可见，模拟不了） | **按路径过滤**错误（只看业务目录与引擎目录）；**判据是"有没有我自己的错误"，不是"构建有没有输出"**（配合第 2 条） |
| 4 | **跨仓库改动时，参考集里的引擎 dll 可能是旧的** | 参考集若取 `Library\ScriptAssemblies\*.dll`（Unity 上次编译的产物），其中 `CloverEngine.*.dll` 是**改动前**那份 ⇒ 业务调引擎**新 API** 会报 `CS0117`/`CS1061`"不存在"，你会误判成"自己写错了"；反过来，拿旧 dll 也能编过已被删掉的旧 API ⇒ **假通过** | 跨仓库（引擎 + 项目）下沉或改引擎 API 时，参考集的引擎 dll **必须用"刚编出来的那一份"**（`compile-check-client.ps1` 的 `csc-out\CloverEngine.*.dll`），⛔ 不要用 `Library\ScriptAssemblies\` 那份；判据：**先跑引擎闸门，再拿它的产物编业务** |

> **第 1 条是最危险的一种失败**：它不报错、不告警，直接让你**在毫无察觉的情况下把没验证过的代码当成验证过了**。
> 凡是"验证手段"本身，都要有一条"**它真的在干活吗**"的自证（覆盖率抽查 / 产物存在 / 对照组）。

## 2. 「编译通过」≠「能跑」≠「像原版」—— 三层验证，缺一层就会"以为做完了"

| 层 | 手段 | 能发现 |
|---|---|---|
| 类型对得上 | 本环路 / Unity 编译 | 拼错的 API、签名不符 |
| 能跑 | PlayMode 端到端断言（见 `experience/verify-recipes.md`） | 关卡没读到、出生点悬空、物件穿模 |
| **像原版 / 像参考** | **像素 diff / 脚本按格判定 + 联络图**（`reference/visual-loop.md` 第八节）；AI 只分诊、人终审 | 版式不对、贴图错位、颜色错 |

**只做第一层就交付 = 半个成品。** 模态自审不是可选项。

## 3. 优先"权威来源"，不要靠肉眼猜

要还原别人的关卡 / 动画 / 预制体用图，**权威来源是工程文件本身**（见 `asset-sources.md` §6）：
解出来的东西**可复查、可重跑**；看图认出来的只能靠"我记得"。
