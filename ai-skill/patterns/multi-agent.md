# 复杂项目：步骤文档 + 多 agent 编排

> 适用：**评估下来比较复杂的游戏/系统**。
> 简单任务（单文件、单个消息号、一个 UI 面板）**不要走这套** —— 直接按 `patterns/game-demo.md` 自己做完，
> 别为了"显得正规"开一堆 agent，那只会增加扯皮和上下文断裂。
>
> **★ 第一铁律先于本文一切规则：必须做完才交付** —— **主 agent 与每个子 agent 都适用**：不许做一点交一点、不许最小可运行版、必须像参考游戏（见 `SKILL.md` 开篇「第一铁律」）。

## 第 1 步：判定复杂度（满足任一条即算复杂）

- **「一键出游戏」（原版级完整成品：启动/菜单/创角链路 + 首场景 + 多系统）—— 一律算复杂**；
- 要同时改**服务端 + 客户端 + UI** 三方，且消息号/协议跨 2 个以上模块；
- 预计代码量 ≳ 800 行，或新增/改动文件 ≳ 10 个；
- 玩法含多个子系统（房间 / 匹配 / 帧同步 / 存档 / 背包 / 排行 / 交易 …）；
- **需要按原版系统清单逐项做完**（菜单 / 创角 / 地图 / 怪物 / 精英怪 / 技能 / 背包 / NPC / 对话 / 掉落 / 商店 / 存档 / 随机地图 / 联机 / 观战 …，见 `patterns/game-demo.md` §0.0c）；
- 存在**可并行的独立子系统**（服务端逻辑、网络层、UI、资源、配表 —— 配表走 `patterns/table.md` 闭环，
  源表放 `策划/数值文档/`，可单独交给一个 agent）。

> **不许砍范围（硬性）**：**该拆多少 agent 就拆多少 —— 10 个、100 个、1000 个都不是理由**。**禁止**因为"要开的 agent 太多 / 周期太长 / 内容太多"而缩小交付范围、降低完成度、或改成"先做个精简版"。人手不够 → **主 agent 继续开**（分批开、逐个验收），直到清单全部做完；**单个 agent 到轮次上限就换手接力**（见下「轮次预算与接力」）。

判定结果要**告诉用户**：为什么按复杂处理、打算拆几步、**打算开多少个 agent（可分批）**。

## 第 2 步：主 agent 先出《步骤文档》（不许跳过，不许边做边补）

落盘：**`clover-{项目名}/docs/步骤文档.md`**（复杂项目才建 `docs/`；`策划/` 只放策划产物 —— `策划/数值文档/` 放配表、`策划/策划案/` 放玩法文档，别混）。

必须包含：

| 内容 | 说明 |
|---|---|
| 目标与验收 | 最终"能跑通什么"，一句话验收标准 |
| **内容清单（原版系统清单）** | 按 `patterns/game-demo.md` §0.0c 列出**要做的每一个系统**（含 ① 启动/菜单/创角链路 ② 首场景全部内容 ③ 游戏内流程），每项标注负责的 agent 与验收标准 —— 这份清单里的项**不允许消失** |
| 系统拆分 | 拆成哪几个可独立交付的子系统 |
| 配表清单 | 需要几张表、表名与后缀（`_cs`/`_c`/`_s`）、字段与主键、谁负责 —— 走 `patterns/table.md` 闭环 |
| 步骤清单 | 每步：产出物（**文件路径**）+ 验收标准 + 依赖的前置步骤 |
| 串/并行标注 | 哪些能并行、哪些必须串行（**先定消息号/协议，再写两端**） |
| 关键契约 | 消息号段、协议字段、模块边界 —— 各 agent 接口对齐的唯一依据 |
| 风险与未知 | 待确认项、需要反问用户的点 |

**《步骤文档》是唯一总纲**：agent 之间不许私自改契约，发现契约有问题 → 先回报主 agent。

## 第 3 步：给每个 agent 一份**自包含**任务文档

落盘：**`clover-{项目名}/docs/agents/agent-NN-{子系统}.md`**。每份必须写明：

1. **身份与技能（强制）**：开头就把「怎么开工」写死，让它照单执行 ——

   ```
   开工先做两件事：
   (1) 拿到 skill：工具集里有 use_skill 就用它加载 clover-engine + unity-cli；
       没有就直接读文件（命中即用，不必读完）：
         · <项目根>/tools/ai-skill/SKILL.md        ← 项目级，首选（记本项目约定 / 消息号 / 配表）
         ⛔ 但**全局 skill 的规则层（§0~§7）不可被项目级覆盖**：两者冲突时以全局为准（§1.10）
         · ~/.codebuddy/skills/ai-skill/  ·  ~/.claude/skills/ai-skill/  ·  ~/.cursor/skills/ai-skill/
         · <仓库根>/clover-tools/ai-skill/SKILL.md  ← 兜底
       （unity-cli 同理，目录名换成 unity-cli/）
       都找不到 → 回报调用方要路径，**不许凭记忆写代码**。
   (2) 然后**按 skill 的「混合模式找依据」查代码**（用户 > 引擎 > 联网/自创），**不许编 API**。
   ```

   > **两点实测提醒**：① IDE 的 agent 定义**不解析 `skills:` 字段**，工具集由 `tools:` 决定
   > （不写 `use_skill` 就没有该工具）；② **别写死绝对路径**（含用户名 / 工具目录），换机器就废。
   > **参考代码的规则不用重写** —— 就是 skill 里那条「混合模式找依据」，别另发明一套。

   负责客户端的 agent **必须**用 `unity-cli` 做编译 / 场景 / 资源 / 日志 / 截图，不得绕开。
2. **任务边界**：只做什么、**绝不做什么**（明确列出不许碰的目录/文件，防止多个 agent 互相踩）。
   **新建项目必须逐字写上这条**：「**只许读本项目（`<项目根>/…`）与引擎源码 / `clover-doc` / skill；
   工作区里**其它** `clover-project-*` 一律不许读、不许 grep、不许照抄**（它的源码 / `tools/ai-skill/` /
   `策划/` / `docs/` / Editor 生成器 / 素材全算）——要抄"通用形状"就看 skill 的
   `patterns`/`scaffold`/`experience`。」**唯一例外**：用户在本轮明确点名了某个工程。
   **并且再逐字写上这条**：「⛔ **不许改任何 skill** —— 项目级 `<项目根>/tools/ai-skill/`、
   仓库里的全局源 `clover-tools/ai-skill/`、宿主的安装副本（`<宿主>/skills/ai-skill/`）**全都不许改**；
   发现 skill 有问题 ⇒ **写进回报**，由主 agent 改。」
3. **前置依赖**：上游已产出的文件 + **确切接口签名**（消息号常量、函数签名、config 字段名）+
   **标准答案那一侧**：参考物解析后落盘的表（`策划/对照表.md` 的"原版值 + 出处"）**或**《原创规格》
   （用户确认过的编号条款）—— ⛔ 没有标准答案就派活 = 让执行者自由发挥。
4. **产出物清单**：要创建/修改的文件**绝对路径**。
5. **验收标准 + 自检命令**：如 `go build ./...`、`dotnet build xxx.csproj`、`unity console tail --format json`。
6. **必读 skill 章节**：把文件路径列出来（`patterns/handler.md`、`reference/conventions.md`、
   `patterns/client/network.md` …），让 agent 直接读，**不许靠记忆写代码**。
7. **日志要求**：按 `SKILL.md`「错误处理与日志（硬约束）」执行 —— **每条非预期分支都要打日志**。
8. **临时文件位置（逐字写上，别省）**：「一切一次性产物（探针 / 驱动脚本 / 临时截图 / 验证小程序）只许放
   `<项目根>/.ai-tmp/test/`（自检宿主放 `.ai-tmp/hosts/`），**用完就删**；
   ⛔ 不许放项目根、`client/_dev/`、`tools/`、`Assets/`、`策划/`、`docs/`。」
   —— ⛔ **尤其不许写成**「探针放 `client/_dev/`」（实测形态：项目级 skill 这么写了，
   子 agent 照章把探针堆到**上百个文件**，违反全局 §1.8；见 `SKILL.md` §1.10）。
9. **收尾自检**：要求它跑完 `SKILL.md` §1.11 的 **7 条**机械自检（项目里若有 `tools/verify.ps1` 就跑它），**把原始输出贴进回报**。
   ⛔ 并且**逐字禁掉"交接文档"**：不许写 `docs/交接-*.md` / `NEXT.md` / `docs/进度*.md`；
   未完成项只写在**回报消息**里（**接力 = 主 agent 立刻开下一个 agent，不是留 md 给未来**，见 `SKILL.md` §1.5 第 8 条）。
10. **批次流水线（逐字写上，别让它自由发挥）**：按 `SKILL.md` §1.13 的**四拍**走 ——
    ① 只读取证 + 产出**改动清单**（每处改什么 + 该处的判据）→ ② **批量改**（⛔ 不编译、不截图）→
    ③ **一次编译 + 预演**（跑廉价自检：离线断言 / 数值探针 / 数据 diff；产出**预演报告**：哪几项已就绪、可截图）→
    ④ **集中出证据**（先出**证据分格表**：格号 / 状态 / **类别** / 判据 → **一条驱动链路按序跑完** →
   采**一次联络图**，格上烧「格号 + 状态 + 关键数值」；脚本按格判定、**AI 只读那张汇总图**。
   格式见 `reference/visual-loop.md` 第八节）。
    ⛔ 明确禁止「改一处编译一次 / 改一处截一次图」；⛔ 同样禁止"为了少编译就跳过 ③④"。
11. **驱动复用（逐字写上，别让它重写一遍）**：开工**先查** `<项目根>/.ai-tmp/drivers/` 与本轮既有驱动 ——
    已有驱动**优先改**，⛔ 不许从零重写（实测：同一套 Play 驱动被 3 片执行者各写一遍、各删一遍，
    每次重建都要重新踩输入注入 / 截图时序 / 日志独占的坑 ⇒ 纯浪费）。
    位置口径：`.ai-tmp/drivers/` = **本轮复用**（交付前统一清）；`.ai-tmp/test/` = **真正一次性**（用完即删）。
12. **实机预算 + 离线优先（逐字写上）**：每进一次 Play 往 `<项目根>/.ai-tmp/test/play-log.tsv` 追加一行
    `ISO时间 / 执行者 / 片名 / 为什么必须进这条链`；**实机预算 ≤ 5 次**（超出 ⇒ 停下来回报，不许继续加会话）；
    **能离线判的（`.ai-tmp/hosts/*check`，秒级）不许进 Play** —— 每条实机断言都要能说出"为什么不能离线判"。
    （依据：`SKILL.md` §1.13 **T0**；闸门见 `reference/verify-template.md` 第 16~18 项）
13. **采集即冻结**：本片的证据一旦采完，**该片被验证的文件即冻结**；要改 ⇒ 该片作废，
    按"改后只重采受影响行"重来，并在回报里说明**这是本片第几次重采**（≥ 3 次 ⇒ 停下回报主 agent）。
    理由与代价：编译是分钟级、进 Play + 注入按键 + 抢拍是分钟级 ×N，断言与 diff 是秒级 ——
    **便宜的多跑，贵的攒一批只做一次**。

> **菜单链路建议单独交给一个 agent**：启动画面 / 主菜单 / 创角·选角 / 读条 / 暂停 / 回主菜单是一整块（`patterns/client/app-flow.md`），与首场景**并行**，契约只依赖消息号与场景名。把它拆出去，是"原版级完整成品"最快成形的一条路径。

任务文档模板：

```md
# agent-NN：{子系统名}

## 0. 技能（开工必做）
- 拿到 skill：有 `use_skill` 就用（`clover-engine` + `unity-cli`）；没有就读
  `<项目根>/tools/ai-skill/SKILL.md` 与全局 skill 入口（路径见任务书顶部的「怎么开工」段）。
- 然后**按 skill 的「混合模式找依据」查代码**（用户 > 引擎 > 联网/自创）；**不许编 API**。
- 必读：{skill 文件路径清单}

## 1. 目标
{一句话}

## 2. 任务边界
- 只做：{...}
- **绝不做**：{不许碰的目录/文件}；不许改契约；不许开子 agent。

## 3. 前置依赖（已就绪）
- 文件：{路径}
- 接口签名：{消息号 / 函数签名 / 字段名，逐条列出}

## 4. 产出物

## 5. 验收标准

- [ ] {功能验收点}
- [ ] **与参考游戏 A 的同角度对照**：本 agent 负责的界面 / 表现**逐项一致**
      （对照清单见 `reference/design-review.md` §3.6；**任何一项"不一致" → 不许回报完成，改到一致**）
      —— **取证按 `SKILL.md` §2 类别**：`数值类` = 运行时日志行 + 断言；`表现类` = 交付前采**一次联络图**
      （格式见 `reference/visual-loop.md` 第八节），**格号写进验收表**。⛔ 不逐项截图、不逐张让 AI 读图

## 6. 约束
- 所有非预期分支必须打日志（见 SKILL.md「错误处理与日志」）。

```

## 第 3.5 步：**怎么派生执行者**（方式错了 = 换了个模型干活）

> **实测出处（匿名）**：主 agent 为了"两片并行、快一点"，用**异步成员通道**一次派了两片执行者。
> 结果执行者的模型落到 **auto**（默认模型），而不是 agent 定义里写的 `model: inherit`。
> 用户当场揪出来：「**为什么要建立 team？team 模型是 auto 啊。你要用和你一样的模型！
> 要不然你就建立子 agent 啊！skill 中没有相关配置吗？**」
> —— 当时 skill 里**确实没写**这条，是这次事故补上的。**下面这句判据本身就是它的存在理由。**

**正确形态：普通子 agent（同步）。**
- 形态：**给 agent 名 + 自包含任务书**（**不带**成员名 / team 名）；
- 只有它会让 agent 定义里的 `model: inherit` 生效 ⇒ **执行者与主 agent 同模型**；
- 它是**同步**的：派活 → 等回报 → 验收 → 再派下一片（第 1~5 步描述的流水线就是这个节奏）。

**⛔ 错误形态：异步成员 / team 通道。**
- 它**绕过 agent 定义的 `model` 字段**，把执行者落到**默认（auto）模型**；
- 代价不只是"模型不同"：默认模型往往更弱，会把"照任务书干活"退化成"自由发挥" ——
  契约、回报格式、§1.11 自检、临时文件位置这些约束会**一起**松掉，而且从回报里看不出来。

**派活后 10 秒核对（无脑照做）**：

| 查什么 | 合格 | 不合格 ⇒ 动作 |
|---|---|---|
| 执行者用的模型 | **= 主 agent 的模型** | 立刻发 shutdown；换普通子 agent 重派 |
| 是否产生了 team / 成员会话 | **没有** | 解散它；**已落盘的产出不回滚**，交给新执行者接力 |

**中止与接力（别把"修错"搞成事故）**：
1. 先让执行者**把进度落盘**（⛔ **不许回滚已完成的文件**）、回一条简短回报；
2. 主 agent 用**正确通道**重派，任务书里把「上一棒做到哪」写进"前置依赖"一节；
3. **谁也没白干**：已产出的代码 / 截图 / 解析结果全部算数 —— 交接的是进度，不是重做。

**为什么不「为了并行」妥协**：一次只派一片确实慢，但**异步通道省下的时间，远小于模型不一致的代价**
（模型一弱，"返工 + 看起来像完成了的假回报"会同时上升）。要快，就靠第 1 步**把片拆细** +
「轮次预算与接力」的**换手**，不是靠换通道。

## 第 4 步：硬约束 —— **agent 不许再开子 agent**

> **每个 agent 都是执行者，不是管理者。**

- **禁止** agent 内部再派生子 agent、再拆分任务、再写"这部分我让别的 agent 做"；
- 理由：**子 agent 会偷懒**。层层转包后没人真正读源码、没人真正跑编译，最后交回一堆"看起来对"的代码，
  主 agent 还得从头返工，比一开始自己做更慢；
- 需要更多人力 → **回报主 agent**，由主 agent 决定是否增开 agent，并**由主 agent 补写任务文档**；
- 每个 agent 必须自己走完：读 skill → 查 `clover-doc` / 源码 → 写代码 → **自己跑编译/日志验证** → 回报结果。

> **但"数量"不设限**：需要更多人 → 回报主 agent，**主 agent 继续开**（10、100、1000 都行，分批开、逐个验收）。**唯一不许做的是"砍范围"** —— 人手不足、周期很长，永远不是缩小交付范围或降低完成度的理由。

## 第 5 步：主 agent 职责（不可下放）

- ★ **不做实现**：**新任务派 agent**；**修 bug 优先激活原 agent**（它上下文还在，最省），
  原 agent 不在了才自己搞 —— 见 `SKILL.md`「谁来做」；
- 维护《步骤文档》，裁决 agent 之间的契约冲突；
- **维护项目级 skill `<项目根>/tools/ai-skill/`**：全部交付完成后，把本次新增的消息号 / handler / 
  面板 / 管理器 / 通用函数 / 配表登记进 `registry.md`，新出现的约束 / 静默风险写进 `constraints.md`
  （**agent 不许各自去改它**，避免并发写冲突）；
- **逐个验收**产出：**自己跑一遍**编译 / 起服 / 读日志，不许"看它说完成了"就通过；
- 不合格 → 让**原 agent** 返工（补充任务文档、指明问题），不要自己顺手改完就算 —— 否则文档与代码失配；
- 全部步骤完成后做**端到端联调**（起服 + 客户端 Play + 关键路径走一遍）；
- **最后一道闸门：参考游戏对照终审**（`reference/design-review.md` §3.6）—— 派 agent 之前就先把 A 的参考截图准备好，交付前**逐个界面/表现配对比对**（启动 / 菜单 / 创角 / HUD / 战斗 / 场景 / 结算）；**有任何一项不一致 ⇒ 不予交付**，打回原 agent 改到一致；**禁止**用"基本一致 / 略有差异"放过；
- 再统一写交付说明与资源清单。**参考游戏名缺失 → 先问用户要**（不许自己挑品类）。

## 轮次预算与接力（跨过物理上限，不靠砍范围）

**事实**：宿主对「**单个任务**的模型请求数」有硬上限（IDE 实测约 500），**没有公开开关**；
撞墙后只能人工回「请继续」续杯。

**推论**：主 agent 与子 agent **各自独立计数** ⇒ 通过「换手」可以跨过它。

**协议**：

1. **主 agent 不做实现**（见 `SKILL.md`「谁来做」）—— 它那 500 轮花在派活与验收上，
   能管 25~50 个子任务；自己下场只会变成一堆半成品。
2. **子 agent 的 `maxTurns` 必须压在上限之下**（本机取 **450**）。写进 agent 定义 ——
   模板与放置位置见 **`scaffold/agent-impl.md`**。
3. **子 agent 到点主动收尾**，回报三段：**已完成 / 未完成 / 下一次该从哪个文件动**。
   **严禁硬撑到被静默掐断** —— 掐断后调用方拿到的是"看起来完成"的残缺结果，这是最贵的事故。
   ⛔ **这三段只许写在回报消息里，不许写成 `docs/交接-*.md` 之类留在项目里**
   （那种文件读起来像"负责任的交接"，本质是**把活推给未来**，与"下一棒继续做"同罪 —— 见 `SKILL.md` §1.5 第 8 条）。
4. **主 agent 接力**：收到回报 → 更新《步骤文档》 → 开下一个 agent（任务文档里带上"上一棒做到哪"）。
5. **不许实现的形态**：因为"怕撞上限"就把系统清单砍短。**上限不是砍范围的理由，是接力的理由。**

## 常见问题

| 问题 | 后果 | 纠正 |
|---|---|---|
| 复杂度没判定，直接开 5 个 agent | 契约对不上，消息号两端不一致 | 先出《步骤文档》，把消息号/协议定死 |
| 任务文档只写"实现服务端逻辑" | agent 自由发挥，接口对不上 | 文档必须带**确切签名 + 产出路径 + 验收命令** |
| agent 自己又开子 agent | 偷懒、无人验证 | 硬禁止；要人找主 agent |
| 主 agent 只看"已完成"不验证 | 交付出错 | 主 agent 必须自己跑编译/日志 |
| 简单任务也走多 agent | 慢 + 扯皮 | 单文件任务自己做 |
| 因为"要开的 agent 太多"砍范围 | 交出来的是精简版，不是成品 | **数量不设限**，分批开；只有"全部做完"才算完成 |
| 只做游戏场景，没有启动/菜单链路 | 一眼假，用户不会用 | 菜单链路单列一个 agent（`patterns/client/app-flow.md`） |
| 只跑通就交付，没和参考游戏比 | 用户一句"不像"→ 大面积返工 | 交付前过 §3.6 闸门；**不一致不许交付** |
| 用户没说参考游戏，AI 自己挑品类 | 做出来**永远不像**，最贵的返工 | **先问用户要游戏名**（可给候选让用户挑，不许自己拍板） |
| **主 agent 自己下场做实现** | 几百轮撞上限，手里只有半成品 | 新任务**派 agent**；修 bug 优先**激活原 agent**（见 `SKILL.md`「谁来做」） |
| 任务文档只写"先加载 skill"、没给路径 | 子 agent 拿不到 skill，凭记忆乱写 | **给出三层路径**（`use_skill` / 全局克隆 / 项目级），见第 3 步第 1 点 |
| 子 agent 硬撑到被静默掐断 | 交出"看起来完成"的残缺结果，最贵的事故 | **`maxTurns` 压在上限之下**（本机 450），到点主动收尾回报 |
| **项目级 skill 把全局硬规则"项目化"放宽**（如把探针位置写成 `client/_dev/`） | 子 agent 照章违规，且"有据可依"、抓不出来 | 项目文档**只许加严**；冲突以全局为准并把冲突行改掉（`SKILL.md` §1.10） |
| 不派下一个 agent，改成写 `docs/交接-下一棒.md` | 读起来像负责，实质是**把活推给未来** | 未完成项**只写在回报消息里**；**接力 = 立刻开下一个 agent**（`SKILL.md` §1.5 第 8 条） |
| 收尾只有"我觉得没问题了" | 临时文件 / 硬规则 / 聚合数字 / 例外登记 / 证据新鲜度 / 复检入口 全没人查 | 跑 `SKILL.md` §1.11 的 **7 条**机械自检（项目里有 `tools/verify.ps1` 就跑它），**原始输出贴进回报** |
| **改一处就编译一次 / 截一次图** | 把最贵的动作（分钟级）重复 N 次：改 30 处 ≈ 半小时纯等待 | 按 `SKILL.md` §1.13 **四拍**走：批量改 → 一次编译 + 预演 → **集中出证据** |
