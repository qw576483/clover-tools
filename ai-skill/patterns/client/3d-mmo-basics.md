# 3D MMORPG 常规业务逻辑清单（动手前必须逐条过一遍）

> 做 3D MMO / 有可操控角色的 3D 玩法时，**这些是"肯定会遇到"的常识项**。
> 不先过一遍就会做出"能跑但没法玩"的东西：按了键不动、动一下被拽回、镜头穿墙、看不到自己…
>
> **⚠️ 这是"清单"，不是"能直接复制的 API"**：每条给的是**做法**。动手前先走 `SKILL.md` 的「★ 混合模式找依据」——
> **用户项目自带 skill、或项目里已有的同类实现，优先采用**（模块名 / 入口 / API 可能与本文完全不同）；
> 本文的示例代码只在"项目确实没有对应实现"时才用，且必须**逐条核对 API 在项目里真实存在**后再写。
>写法依据：① 本仓实测（标 **实测**）；② 业界标准做法（标 **标准**，见文末来源）。
> 环境前提：**只支持 Unity 6（6000.x）**。

## 0. 一张表：症状 → 真因 → 做法

| 症状 | 真因（按概率排） | 做法 |
|---|---|---|
| **血条永远满 / 一整条深红，扣血也不变** | UI 里用了 `Image.Type.Filled` + `fillAmount`，但这个 Image **没有 sprite** —— 无 sprite 的 Filled Image 会退化成整块矩形，`fillAmount` **静默失效** | 两种正解：① 给 Image 一张 1×1 白 sprite 再用 `fillAmount`；② **改用锚点宽度**（`anchorMax.x = ratio`，`type = Simple`），不依赖任何 sprite。世界空间血条同理（用两个 Quad 的 localScale） |
| **角色/模型渲染成纯白（无贴图）** | 调色板贴图**没跟着 FBX 一起进 Resources**（KayKit 等素材包约定：材质名 = 贴图名、同目录）。材质在、`mainTexture` 却是空 —— 数字看不出来，**只有看图才发现** | 把 `<model>_texture.png` 复制到与 FBX **同目录**，然后 `AssetDatabase.ImportAsset(fbx, ForceUpdate)` 重导，让导入器自动关联；验收时打印 `material.mainTexture` 是否为空 + **看图** |
| **玩家一进图就被围殴 / 被看不见的敌人持续掉血** | 仇恨（aggro）是**全局状态**：没有时效、离图/死亡时不清 ⇒ 玩家离线/挂机/换会话后假人继续"追着打"，一进门就挨打 | 三件套：① 记仇**有时效**（一段时间没再被打就忘记）；② 玩家**离图/死亡**时清除对他的记仇；③ **"谁打的我"必须可见**（HUD 提示 + 飘字颜色区分），否则玩家会理解成"我一挥剑自己就掉血" |
| **玩家砍靶子时自己掉血 / 被慢慢磨死** | **设计错误**：靶子默认会还手，而近战**必须站在攻击距离内**才能打到人 ⇒ 站着砍就必然被反击。**调数值解决不了**（13→6→4 只是把死亡从 5 秒拖到 25 秒，体感仍是"我一挥剑自己就掉血"） | 三条一起做：① **普通靶子永不还手**（协议加 `hostile=false`，服务端在"反击"与"记仇"两处双重把关）；② **会还手/会伤害玩家的东西必须显式开启**（单独按键/单独入口，HUD 标注"会还手"）；③ 加**脱战回血**（如 6 秒没挨打 +2HP/秒），消除"慢性死亡"。验收口径：连砍 N 下后 `我打中目标=N 次 && 目标打到我=0 次 && 血量不变` |
| **敌人头顶血条"满血只画一半"（如 60%）** | 属性推送只处理了 `hp`、**把 `max_hp` 丢了** ⇒ 上限落到默认值（如 100），而怪是 60 血 | 同时处理 `hp` 与 `max_hp`（两种命名都认）；**实体生成时补推一次初始 `hp/max_hp`**，否则血条在第一次挨打前没有正确初值（见 §8） |
| **重连/换会话后角色"活着但动不了、打不到任何东西"** | 服务端还留着上一次的**死亡状态**而客户端以为自己活着（客户端还常用"hp<=0 就当满血"的兜底把真实状态蒙掉）；或幂等进图分支没做 `bindScene`/`SetViewRadius` ⇒ Move 被"不在任何场景"静默拒绝 | 服务端**进图即复活**（回出生点+满血+清限频窗口+推 respawn）；客户端**如实反映** `hp<=0` 并弹死亡遮罩；装配完成时同步一次死亡状态；幂等分支补记账与视野半径 |
| **走动时一直播同一个动画（像滑步）/ 攻击不像攻击** | ① 状态机没设默认状态或状态顺序错位 ② 用"多状态 + 阈值过渡"而不是 BlendTree ③ 参数名与 `SetFloat` 不一致（**静默**）④ Animator 挂在错的物体上/开了根运动 | 见 §7：显式 `defaultState`、`Speed` 驱动 **1D BlendTree**、参数名统一并**自证打印**、关根运动；验证必须**读状态名**，不能靠眼睛 |
| **打敌人没反馈 / 敌人没有血条 / 一堆橙色小球** | ① 只做了自己的 HUD，缺**世界空间头顶血条** ② 占位胶囊在模型加载成功后**没被移除** ③ 占位色用了像角色的亮色 | 见 §8：头顶血条 + 命中三件套（飘字/音效/目标血条）；占位物加载成功**立即移除**、失败要告警并用"明显是占位"的样式 |
| **「只能原地移动」**（角色在跑动画，位置一动不动 / 只有个别方向能动） | ① **出生点落在"位图可走、角色半径占不下"的位置**（贴着建筑/边界的夹角）——角色一出生就不合法 ② **本地碰撞在"当前就站不住"时彻底锁死**：脚下不合法 ⇒ 每个候选点也要先过"能否站立" ⇒ 一条轴都放不出去 ③ 按键链路（`IsLocked` / 后端 / TimeScale） | ① **引擎加载地图时已自动做出生点净空校验**：中心 ±1 格全可走，否则**环形搜索**最近的净空格心并打日志（`pkg/domain/mmo/mapdata/spawn.go`）—— 业务不用管，但**摆出生点标记时要避开建筑夹角** ② `Resolve` 加**解除卡死**规则：`if (!CanStand(from, r)) return IsWalkable(to) ? to : from;` ③ 先量输入链路，再量"**意图速度 vs 实测位移**"（HUD 直接显示：意图 6.0 / 实际 0.0 ⇒ 就是被碰撞吃掉），最后用探针打 `CanStand` + 八向可走 + 四方向位移 |
| **看不到自己**（`views=0`，操作三件套装不上） | 指望 AOI 会把自己的 enter 事件发给自己 —— **不会** | 收到**进图回包**时显式创建自己的视图（`SetSelfId` + `EnsureView(selfId)`）；对"回包前进入视野的实体"先排队、等 self id 到达再补建 |
| **同一条事件客户端收到 N 份**（一次命中打 4 条日志） | 把 `scene.Around` 的**全部对象**当推送接收者（假人没有连接，`PushToPlayer` 不报错却会被投递） | 接收者 = **观看者**：过滤出"进过图的真实玩家"再推；移动/属性/战斗三条推送统一走同一个 `viewerIDs()` |
| **引擎报 `Handler error [X]: A cannot be converted to B`** | 业务事件名**与引擎内部事件撞车**（引擎自己 Emit `Net.SceneChanged`/`Net.Alert`/`Net.PlayerFullSync` 等） | 业务事件统一加**自己的域前缀**（如 `App.*`）；域名 = 归属方，别蹭引擎的名字 |
| **伤害/数值离谱**（一下秒杀、血量当攻击用） | 多返回值**接错位置**（`atk, _, _, _ := f()` 而 `f` 返回 `(hp, maxHp, atk, def)`）——编译、vet、公式单测**全绿** | 返回处写清顺序注释；测试把**期望数值写死**（如"打假人 19 伤害、4 下击杀"）；端到端断言具体值而不是"大于 0" |
| **刷出来的靶子/假人跑没影、够不着、永远打不死玩家** | 活靶子没有巡逻范围、且**不还手** ⇒ 玩家一个人打靶，**死亡→复活这条链路永远没被执行过** | 假人加**巡逻半径**（离出生点折返）+ **记仇反击** + **原地重生**；回归用例用 `step=0` 的静止靶子 |
| **PlayMode 用例"避障失效/事件重复"** | ①没等**真实时间**（30 帧 ≈ 0.1s，平滑跟随没收敛）②清理用 `Destroy`（延迟到帧末，上一用例的墙被下一用例探到）③活编辑器里测试与场景 Bootstrap **抢同一个 `Game`/连接** ⇒ 计数虚高 | 用 `WaitForSeconds` 等收敛；`DestroyImmediate` 隔离；**是否重复投递以服务端日志为准**；PlayMode 测试必须 `--async_tests` + 轮询 `test_status` |
| **按 WASD 不动** | ① 直连 `Keyboard.current` 但工程是旧输入后端（拿到 null）；② 自己的位置每帧被服务端权威位置覆盖 | 走 `Game.Input`（后端无关）；自己位置用**本地预测**，权威位置只做校正 |
| **往前走一下就被拽回来（橡皮带）** | ① 客户端**没有本地碰撞**（能穿墙/出图）→ 服务端拒绝 → 误差越拉越大 → 硬贴回；② 同一个账号有**两个客户端**在互发位置（重复挂载/重复登录）；③ 断线重连后未重新登录却仍在发消息 | ① 客户端用**同一份地图数据**做本地碰撞（见 §2）；② 场景内**单实例守卫** + 不重复登录；③ 接全 §4 的重连/重登 + 未进图**停发**闸门 |
| **镜头穿墙 / 被墙挡住却不动 / 看不到角色** | 把"最小距离"当硬下限 → 被挡时仍把机位留在墙里 | §3 的六条：多高度探针 + 允许拉近 + `CheckSphere` 兜底 + 收缩快恢复慢 + 贴脸隐藏角色 + 不钻地（**实测**） |
| **服务端日志被同一原因刷屏** | 高频路径（每帧/20Hz/断线重连）里失败日志没降频 | 首次 + 每 1000 次（**实测**：一次断线刷 3262 条；一次未鉴权刷 747 条） |
| 攻击只有动作没反馈 | 缺战斗闭环（伤害/HP/命中/死亡/复活） | §5；这是"完整版"的必做项 |
| 面板打不开 | `Game.UI.Open<T>()` 找不到 `Resources/UI/{类名}` 预制体（只打 Error 后 return） | 用 Editor 脚本生成真预制体 |

## 1. 移动同步：预测 + 校正 + 回放（**标准**）

```
客户端每帧：读输入 → 本地碰撞解算 → 立即表现（零延迟手感）
每 50ms(20Hz)：把「当前本地位置 + 递增 seq」发给服务端
服务端：校验（可走性 / 单步上限）→ 接受则更新并广播；**拒绝则回一条校正（带 ack=已处理到的 seq）**
客户端收到校正：① 位置 = 权威值 ② 丢弃 seq ≤ ack 的未确认输入 ③ **回放剩余未确认输入**
```

**为什么不能"直接用权威位置覆盖本地"**：客户端是"现在时"，服务端状态是"过去时"；
直接覆盖必然出现"往前走两格 → 退回一格 → 再前进"的橡皮带（Gambetta 文中原文例子）。
正确解法就是上面的「ack + 回放」，回放这一步不能省。

工程要点：

- **接受时不回包**（省带宽），但客户端要有**未确认输入的滑动窗口**（≈ 一个 RTT，20Hz 下 8 条）；
- 服务端**拒绝时一定要回校正**，否则客户端继续瞎走、误差累积成硬贴回；
- 移动帧走不可靠通道（`SendUnreliable`）没问题，但**关键结论（校正）用可靠通道**（`PushToPlayer` 默认可靠）；
- **未进图 / 断线期间必须停发**（`SendEnabled` 闸门）—— 否则会被网关按 `unauthenticated` 拒掉并刷屏（**实测**）。

## 2. 客户端本地碰撞必须与服务端**同一套规则**（**实测踩过**）

- 数据来源：**用引擎烘焙器（`Clover/地图烘焙`）一次写两份同源字节**
  （`Assets/MapData/` 服务端 + `Assets/Resources/MapData/` 客户端，CloverMap 二进制 v1）；
  ★ **不要自己写地图格式 / 解码 / 格换算** —— 直接问引擎 `Game.Map.WalkableAt()`：
  它读的是服务端加载的**同一份字节**，格换算（floor 取整）、越界、位图方向由引擎保证两端口径一致
  （契约见 `clover-server-engine/pkg/domain/mmo/mapdata/README.md`）；
- **角色半径采样**：中心 + 8 向（半径 0.35m）→ 避免"半个身子插进墙里"（**半径取多少是手感，属业务**）；
- **分轴解算（先 X 后 Z）**：撞墙时贴墙**滑行**，而不是一头撞停（手感关键）；
- **扫掠细分（每段 ≤0.25m）**：只检查终点会**穿墙**（**实测**：一次 7.5m 位移从建筑左侧直接跳到右侧，判定却是"可走"）；
- **边界**：以上三条**刻意留在业务**（客户端引擎 `结构规则.md` §3.1「引擎不做本地预测」）——
  引擎只给"这一格能不能走"这个空间事实，用多大半径、几点采样、撞墙是停还是滑都是玩法手感；
- 自证方式：写个 `verify-*.cs` 用编辑器 `eval_file` 跑"小步前进 N 次 + 大位移一次"，断言终点与撞墙步数。

## 3. 第三人称相机（**标准**，六条缺一不可）

| # | 做法 | 不做的后果 |
|---|---|---|
| 1 | **多高度探针**（注视点 ±0.5m、+1.0m 各打一条 `SphereCast`），取**最小**可用距离 | 只探一条射线时，墙沿/门框会让相机"露缝看穿" |
| 2 | **被挡时允许拉到很近**（`MinDistance` 0.2m 左右），**不能**把它当硬下限 | 机位被留在**墙体内部** → 表现为镜头穿墙/看不到角色（**实测**） |
| 3 | **机位重叠兜底**：`Physics.CheckSphere` 仍重叠就继续拉近（有次数上限） | 贴脸场景仍会穿模 |
| 4 | **收缩快、恢复慢**（如收缩 30/s、恢复 6/s 的指数逼近） | 出现即穿模，或障碍离开时镜头"弹跳" |
| 5 | **贴脸时隐藏角色模型**（< ~0.85m 关 Renderer） | 模型糊满屏幕 |
| 6 | **机位不得低于地面**（`y = max(y, 0.35)`） | 俯角为负时镜头钻进地里 |

其它常规：

- 操作：**右键拖拽**转视角（不锁鼠标光标，避免抢 UI 点击）、滚轮缩放、pitch 限制（如 -25°~75°）；
- **不要用引擎的 `Game.Camera.Follow` 做第三人称**：它只是"锁 Z 的简单跟随"
  （`Runtime/Presentation/Camera.cs:57-63`，无环绕/无旋转/无防穿墙）；**不调用它**，自写相机就不会被抢 Transform；
- 自证方式：把角色瞬移到障碍旁 → 设相机朝向墙侧 → 读"相机-角色距离"（**实测**：被挡 1.47m / 无遮挡 6.36m）。
  两个数字口径要说清：`6.36m` 是**相机→角色根**的实测距离，配置里的 `5.5` 是**相机→pivot**（pivot 抬高约 1.35m）；`1.47m` 是被墙挡住后的收缩值。

## 4. 断线重连 / 重登（**标准**，引擎已给全套事件）

引擎事件（`Runtime/Network/NetworkManager.cs:72-75` 的类注释）：
`Net.OnConnected / Net.OnDisconnected / Net.OnConnectFailed / Net.OnKicked /
Net.OnResumed / Net.OnResumeFailed / Net.OnUnauthorized`。

业务必须做的事：

| 事件 | 业务动作 |
|---|---|
| `OnConnected`（每次连上都会发，含首次） | **只有"曾登录过且本连接未绑定"**才重新登录（否则会对同一账号登录两次） |
| `OnDisconnected` | **立刻停发**（`SendEnabled=false` + 出图状态），避免未鉴权刷屏 |
| `OnResumed` | 会话恢复了 → **重新进图**（服务端可能已把你移出场景 / 位置需重新对齐） |
| `OnResumeFailed` | 标记未绑定；等下次 `OnConnected` 重新登录（**不要**在这里硬发业务消息） |
| `OnUnauthorized`(401) | 同上：停发 + 等重登 |
| `OnKicked` | 重连次数耗尽 → 明确提示玩家（需重启客户端） |

**登录重入保护**：`LoginFlowAsync` 加 `_loginInFlight` 闸门（**实测**：Start 与重连两条路径都触发 → 重复登录 → 旧连接绑定被顶掉 → 该连接变 `unauthenticated` 仍狂发消息）。

## 5. "完整版"还需要的常规项（做 3D MMO 时按序补齐）

| 项 | 要点 |
|---|---|
| **启动 / 菜单链路**（最先做） | 启动画面 → 主菜单 → 创角（或选角）→ 读条进图 → 暂停 → 回主菜单；**没有完整游戏是直接进游戏场景的**。写法见 `patterns/client/app-flow.md` |
| **单实例守卫** | `Awake` 里 `FindObjectsByType<Bootstrap>()`，多于 1 个就自毁重复的 —— 两个客户端同账号同 objID 会**互相拽回**（**实测**） |
| **战斗闭环** | 攻击 → 距离/朝向校验 → 伤害 → HP 广播 → 命中/受击/死亡动画 → 复活；**动画与音效在每一环都要触发** |
| **目标选择** | 点击/最近目标选择 + 目标框 + 血条；HUD 显示目标信息 |
| **音效触发点** | 脚步（按速度）、挥砍/命中/受击、UI 点击、进图/升级；音量分组（`SoundGroup`） |
| **HUD** | 血/蓝条、目标框、小地图、聊天、快捷栏；走 `Game.UI.Open<T>()` + `Resources/UI/{类名}` |
| **点击寻路** | 服务端 `mapdata.FindPath`（`NavGrid3`）→ 返回路点 → 客户端沿路点走（不要客户端自己算权威路径） |
| **地形高度** | 平地也要预留：服务器 `WalkableAt` 之外还有 `NavGrid3` 分层；跳跃的 Y 要透传（AOI 是三维球体） |
| **交互** | 拾取 / NPC 对话 / 传送点：距离校验在服务端，客户端只发起意图 |
| **带宽** | 位置 20Hz 不可靠；状态变更（HP/装备/进图）走可靠；视野进出**必须可靠**（丢一条客户端永远不知道实体存在） |

## 6. 服务端侧还没做但迟早要做的（登记，不装看不见）

- **同账号顶号**：同一账号二次登录时应**踢掉旧连接**（并把旧连接标记为失效，拒绝其后续消息），
  否则"两个客户端同账号"会互相拽回、刷日志（本次已实测到该现象）。
- **移动频率/距离上限**：已有单步上限（`maxStepPerMsg`），还应加"每秒距离上限"，防加速挂。
- **移动合法性日志降频**：拒绝类日志已按"首次 + 每 N 次"降频，沿用同样口径。

## 7. 角色动画：接对了才"像在跑"（**实测踩过**：一直是第一个动画 / 攻击不像攻击）

**症状**：走动时角色一直播同一个动作（像滑步），攻击看不出是攻击动作。

**四件事缺一件就"动画不对"**（按排查顺序）：

| # | 事 | 为什么 | 做法 |
| --- | --- | --- | --- |
| 1 | **状态机默认状态显式指定** | 不指定时取"第一个加入的状态"，顺序一变就整体错位 | 生成脚本里显式 `stateMachine.defaultState = idle` |
| 2 | **Idle/Walk/Run 用 1D BlendTree（Speed 参数）** | 用"三个状态 + 两条阈值过渡"会在阈值附近抖/卡住，过渡还依赖 exitTime，看起来就是"接不上" | 一个 BlendTree，`Speed` 0/1/2 分别绑 Idle/Walk/Run，插值交给 Animator（这才是"动画接动画"） |
| 3 | **参数名与驱动方必须一致** | 驱动方写 `SetFloat("Speed")` 而状态机里参数叫别的 ⇒ 过渡永不触发，**且完全静默** | 参数名一处定义、生成脚本与运行时共用；自证时打印 `ctrl.parameters` 与 `an.GetFloat("Speed")` |
| 4 | **Animator 在模型实例上，且关根运动** | 位置由业务本地预测驱动，开根运动会与预测打架（位移翻倍/漂移） | `applyRootMotion=false`；`cullingMode` 不要 `CullCompletely` |

**验证方式（不许靠眼睛）**：

- 读 `Animator.GetCurrentAnimatorStateInfo(0).IsName("Run")` + `GetCurrentAnimatorClipInfo(0)[0].clip.name`；
- 打印 `an.GetFloat("Speed")`（走动时应 ≈1）与 `ctrl.parameters`（列出全部参数名）；
- 过渡中读 `IsInTransition(0)` / `GetNextAnimatorStateInfo(0)`。

**攻击动画**：Trigger 进、`hasExitTime` 出（播完自动回 Idle）；**角色要转向目标**，
否则"打在空气里"；命中反馈必须**三件套同时出现**：飘字 + 音效 + **目标血条下降**。

## 8. 敌人/他人实体：必须有"头顶血条"，且不能出现占位物

| 项 | 要求 | 反面 |
| --- | --- | --- |
| 头顶血条 | 每个实体头顶一条**世界空间**血条（跟随实体、随伤害下降）；自己的血条在 HUD | 只做了自己的 HUD，打敌人没有任何反馈 ⇒ "打不到人"的错觉 |
| 占位物 | 模型异步加载期间可占位，但**加载成功必须立刻移除**；加载失败要打警告并显示"缺资源"标记 | 屏幕上一堆**橙色小球/胶囊**（占位胶囊没被移除）⇒ 玩家一眼看出是半成品 |
| 名字/等级 | 有对战要素时头顶还需要名字（可选，但要有地方放） | 分不清谁是谁 |

> 判定"打没打中"的**唯一可信信号**是目标血条下降 + 飘字；只播自己的挥砍动画 = 没有反馈。
