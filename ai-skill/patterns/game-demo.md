# Game Demo 一键交付 SOP（**原版级完整成品** · 启动/菜单/创角链路 + 首场景 · 真资源 + 动画必接）

> 本范式回答一个问题：**"帮我实现一个 XX 游戏 / demo / 玩法原型"** 进来后，AI 该怎么一步步产出
> 「**和原版一模一样的完整成品**：从启动画面 → 主菜单 → 创角/选角 → 读条进图，到首场景全部系统（操作 / 战斗 / 技能 / 背包 / NPC / 精英怪 / 随机地图…），能编译、能连服、**画面/操作/动画/音效都是成品级**」的可交付游戏。
>
> **⚠️ 起点不是零前提：本 SOP 是「从 0→1」的做法，动手前先走 `SKILL.md` 的「★ 混合模式找依据」** —— 
> ① **本项目自己**的 skill → ② **本项目里**已有的同类代码（**沿用它的 API / 模块名 / 入口 / 目录**）→ ③ 才用本 SOP 的示例。
> 用户项目可能已有自己的实现且**整套 API 都不一样**：**冲突时以用户项目为准，禁止照抄示例**（示例只给形状，不给能直接复制的 API）。
>
> ⛔ **新建项目时另有一条红线**：工作区里**别的** `clover-project-*`（及其 `client/`、`tools/ai-skill/`、
> `策划/验收表.md`、`Assets/Editor/*.cs` 生成器、素材）**一律不许读、不许 grep、不许照抄** ——
> 上面 ① ② 说的"项目"只指**本项目自己**。新项目的一切（目录 / 模块 / 面板 / 生成器 / 配表 / 素材来源）
> **从 0 自己设计**；只有引擎源码、`clover-doc`、本 skill 的 `patterns`/`scaffold`/`experience` 可作**通用形状**参考。
> 唯一例外：用户在**当前这一轮**明确点名"参考某个已有工程"。
>
> **★ 第零铁律先于本文一切规则：做游戏 = 1:1 复刻，不许思考、不许发挥** ——
> 「A 有 ⇒ 做；A 没有 ⇒ 不加」是唯一判据，不许改 UI / 换素材 / 调数值 / 简化系统 / 自称"致敬·改编·重制"，
> 也不许先写"我的方案 / 取舍建议"给用户看（见 `SKILL.md` 开篇「第零铁律」）。
> **没有参考物时怎么办**：只报品类 → 问一次（给 2~3 个标杆候选）；说"你定" → AI **自选**标杆（同品类 / **载体可得** /
> 规模可交付 / **只告知不等待**）；**明说做原创** → 标准答案换成《**用户规格书**》、出处换成**条款编号**
> （判据不消失，只换来源）—— 见 `SKILL.md` §0 的两节。
> **注意区分**：**开工前把需求问清（参照哪款 / 单机还是联机 / 平台基准 / 范围边界）是鼓励的**，一次问完即可
> （见 `SKILL.md` §3「开工前的澄清窗口」）；被禁的是"问要不要做 / 问进度 / 求许可"。
>
> **★ 第一铁律先于本文一切规则：必须做完才交付** —— 不许做一点交一点、不许最小可运行版、必须像参考游戏（见 `SKILL.md` 开篇「第一铁律」）。
>
> **五条底线（压倒其它一切考虑）**：
> 1. **交的是"完整成品"，不是半成品、更不是骨架** —— **① 启动/菜单/创角链路 + ② 首场景全部内容 + ③ 游戏内流程（暂停 / 结算 / 回主菜单）**，三段缺一不可；**世界上没有一个完整游戏是"打开就直接站在游戏场景里"的**。**禁止**把纯色块 / 内置 Cube / "动画留空实现" / "框架已预留" 当交付。
> 2. **像原版** —— 原版有的系统 / 菜单 / 手感 / 数值 / UI 布局 / 音效时机，**逐项做出来、一摸一样**；`§0.0c` 清单里**空着的行就是没做完**。
> 3. **有角色就必须有操作** —— 第三人称（或第一人称）**相机 + 移动**必须真的可用：WASD 生效、鼠标能转视角、相机跟随不抖不穿墙。**禁止**上帝视角俯视。
> 4. **用户必须"看得到"工程** —— 建完登记进 Unity Hub 并置顶，交付说明写清「Hub 里的名字 + 绝对路径」（见 `reference/unity-cli.md` §6.1）。
> 5. **按成品标准做** —— 优先**直接采用同类参考游戏的成套素材**，成套使用保证画风统一；**本项目非商用 ⇒ 不设许可门槛，能下到合适的就用**（只需记一行来源）；只有"登录 / 会员 / 付费 / 点按钮"才让用户下。
>    占位（纯色块 / 空实现）**只是兜底，不是交付形态**。
>
> **不许砍范围（硬性）**：**时间 / token / 规模 / agent 数量都不是理由**。复杂就拆多 agent（`patterns/multi-agent.md`，**10 个、100 个、1000 个都行**），**不许因为"内容多 / 要拆很多 agent"缩范围或降完成度**。
> **为什么这么硬**：用户如果觉得我们连"菜单 + 创角 + 首场景"这点东西都做不出来，**压根就不会用我们引擎** —— 交付的 demo 就是引擎能力的唯一证明。
>
> **验收必须自己跑过**：编译 → **按分格表用一条驱动链路进 Play 跑完**（⛔ 不逐项进出）→
> 按**类别**取证（`数值类` = 日志/断言；`表现类` = 采一次联络图），见 `SKILL.md` §2 硬性判定第 3 条与 §1.13 四拍
> （`reference/unity-cli.md` §8.1）。

## 0.0 参考游戏保真协议（**动手前必做**；用户没给游戏名就先问）

> 目标：玩家一眼就认得出"这就是 <A>"。**手感 / 操作 / 镜头 / UI / 动画 / 音效 / 场景**都按 A 来。
> **不许凭印象开工**，也不许说"不知道 A 什么感觉"就算了 —— 去搜。

### 第 0 步：必须拿到参考游戏名（**用户没给 → 停下来问**）

- 用户点名了游戏 A → 用 A；
- **用户没给游戏名 → 停下来问用户"参照哪款游戏"**（可给 2~3 个同品类候选让用户挑，但**不许自己拍板**）；
  **只报了品类（"做个 MMO / 做个塔防"）也一样要问** —— 品类不是参考物，细则见 `SKILL.md` §0「用户只报了品类怎么办」；
- **禁止**"我自己挑个同类型的吧" —— 做出来必然"不像"，等用户看到再返工是最贵的路径；
- 拿到名字后先产出 `策划/策划案/{A}参考规格.md`，再动手写代码。

### 第 1 步：研究 A，把"可实现的规格"抄成文档

```bash
# 多搜几轮、中英文都搜；搜的是"能落成代码的量"，不是剧情
web_search "<A> 操作手感 movement 数值 移动速度 武器参数 镜头 FOV UI 布局 音效"
web_search "<A> gameplay mechanics movement speed jump height weapon stats UI layout"
```

产出 `策划/策划案/{A}参考规格.md`，至少覆盖：

| 维度 | 要抄下来的 |
|---|---|
| 操作 | 键位、第一/第三人称、鼠标灵敏度、有无加速/惯性/蹲/跳/冲刺 |
| 镜头 | 视角高度、FOV、后坐力/晃动、是否有瞄准缩放 |
| 数值 | 移动速度、跳跃高度、射速/伤害/冷却、回合或关卡时长 |
| UI | 屏幕各位置显示什么、字体层级、准星/血条/弹药样式 |
| 表现 | 动画状态机（idle/run/attack/hit/death）、特效、音效触发点 |
| 节奏 | 一局多久、胜负条件、核心循环、复活规则 |

### 第 2 步：素材必须来自 A（或 A 的同源）

见 §4.0 四级链：**A 自己的素材 → 同类游戏成套素材 → 我们的兜底素材（自动下载先用）→ 让用户下**。

### 第 3 步：逐项对照实现，并把它作为交付验收表

| 项（来自 A） | A 的表现 | 我们的实现 | **类别**（数值类 / 表现类） | 状态 |
|---|---|---|---|---|
| 移动速度 | 6.0 m/s | `PlayerMotor.RunSpeed = 6` | ✅ |
| 镜头 | 第三人称后视 | `ThirdPersonCamera`（pitch 16，可调） | ✅ |
| 攻击 | 左键挥砍 + 命中反馈 | 已播攻击动画；**伤害/命中未做** | ❌ 待做 |
| … | | | |

> **这张表就是"完成度"的可验收形式：空着的行 = 还没做完 ⇒ 不许交付。** 
> 允许为了做到位花很久；但**不许拿"最小可用"交差**。

### 第 4 步：**交付前自审：像不像 A？**（**不通过 = 不可交付**）

**这不是建议，是闸门。** 交付前必须把"自己的成品"和"参考游戏 A"并排比一遍；**不像就是不可交付版本**，改到一样为止。

1. **准备对照物**：A 的真实截图 / 视频切片（启动 / 主菜单 / 创角 / HUD / 战斗 / 场景 / 结算）存 `策划/参考图/`；自己的**同样角度**画面存 `策划/自审对比/`，一一配对 ——
   **采集形态与判定见 `reference/visual-loop.md` 第八节**（联络图：一条链路采一次、脚本按格判定、AI 只读汇总图一次）；本步只管**判据**（一致 / 不一致），不管逐张采集；
2. **逐项对照**（每项写 `一致` 或 `不一致（差在哪）`，**不许写"基本一致 / 大致像"**）：菜单层级与按钮文案、创角字段与布局、HUD 位置/比例/配色/字号、移动速度与转身、攻击节奏与镜头、动画切换、命中反馈三件套、场景风格与色调、音效时机、节奏时长；
3. **判定**：**只要有一项不一致 ⇒ 该版本不可交付** —— 改 → **按批次**重新采一次联络图 → 重新对照，**循环到全部一致**（⛔ 不是"改一项就重截一项"，见 `reference/visual-loop.md` 第八节）；
4. **必须看图**：`表现类` 的项**进联络图**、AI 只读那张汇总图一次（`reference/visual-loop.md` 第八节；`reference/design-review.md` §3.4）；**数字全对但画面不像 = 不合格**；
5. **禁止**把"不一致"写进交付说明当免责（"这部分略有差异 / 后续可优化" = 没做完）。

## 0.0b 策划自审：先出《行为 → 表现规格》表（**在写任何代码之前**）

「一键出游戏」不是"把功能堆出来"，而是"把一个**说得清的玩法**做对"。
所以第 0 步不是建工程，而是**策划自审**（完整模板与感官验收清单见 `reference/design-review.md`）：

1. 用 5 问说清这个游戏（类型/参考游戏、核心循环、每个行为的表现、数值与节奏、哪些"不行"是设计内）；
2. 把核心循环里**每个行为**填进《行为 → 表现规格》表：**画面 / 动画 / 声音 / UI·数值反馈 / 网络 / 验收方法**；
3. 不知道就先搜参考游戏，搜不到就写"不确定"并问用户 —— **不许凭感觉糊**；
4. 这张表**同时是交付验收表**：交付前**按分格表用一条驱动链路跑完**（⛔ 不逐项进出 Play）——
   **每行标「类别」**（`数值类` = 日志/断言即可；`表现类` = 必须进联络图），见 `SKILL.md` §2 硬性判定第 3 条
   （感官项细则见 `design-review.md` §3.1）。

> 反例（真实踩过）：动画状态机没接好（一直播第一个动作）、攻击无命中反馈、敌人没有血条、
> 占位胶囊体当敌人还没隐藏 —— 每一项都"能跑"，但没有一项像游戏。

## 0.0c 原版系统清单（**动手前先列，逐项做完，不许砍**）

> 这不是"可选清单"，是**交付合同**：动手前把 A 的系统清单写进 `策划/策划案/{A}参考规格.md`，一行一个系统，写清「做法 + 验收方法 + 状态」；**空着的行 = 没做完，不得交付**。

**列清单的方法**：照原版从"打开游戏"到"玩完第一个循环"走一遍，**每一步都记下来**：

1. **启动链路**：启动画面 / Logo / 厂商字 → 主菜单（开始 / 继续 / 设置 / 退出；联机加登录 / 注册）→ 创角（名字 / 外观 / 职业 / 属性）或选角 → 读条 → 进游戏；
2. **游戏内**：地图（含**随机地形**）、NPC 与**对话**、商店、普通怪、**精英怪与词缀**、Boss、技能与技能树、背包与装备、掉落与拾取、任务、传送 / 回城、存档、图鉴；
3. **游戏内流程**：暂停菜单、设置、结算、回主菜单、退出；
4. **联机类**（联机玩法）：登录 / 注册、匹配 / 房间列表、选阵营、观战、记分板、断线重连。

**示例（不是模板 —— 按 A 的真实内容列）**：

| 游戏 | 必做清单（节选） |
|---|---|
| 暗黑破坏神 2 | 启动画面 / 主菜单 / **创角（职业·外观·属性点）** / 进游戏 / 地图与**随机地形** / 普通怪 / **精英怪与词缀** / 技能与技能树 / 背包与装备 / NPC 与**对话** / 商店 / 掉落 / 传送（回城书）/ 存档 / 回主菜单 |
| CS | 主菜单 / **选阵营** / 买枪与经济 / 地图 / 射击与后坐力 / 命中反馈 / 观战 / 联机匹配 / 记分板 / 回合结算 |
| 梦幻西游 | 启动 / 登录 / **创角（门派·加点）** / 主城 / NPC **对话**与任务 / 背包 / 商店 / 战斗（回合）/ 组队 / 结算 |

**硬规则**：

- **禁止**用"范围太大 / 内容太多 / 时间不够 / 下次再做 / 框架已预留暂未实现"结案；做不完就**拆多 agent**（`patterns/multi-agent.md`），**不是砍范围**；
- 清单里的项**允许排优先级**（先做能串起主循环的），但**不允许消失** —— 全部做完才算交付；
- 原版**手感 / 数值 / UI 布局 / 音效时机**同样进清单（对照 §0.0 参考规格逐项对齐）。

## 0. 范围：**原版级完整成品**（不做 MVP、不做"最小可用"、不做"骨架"）

用户说"一键出暗黑2 / 梦幻西游 / CSGO2 / 皇室战争 / 魔兽世界 / 杀戮尖塔…"，
**"一键出" = 交付这个游戏的完整成品**，三段都要有：

| 段 | 内容 | 缺了会怎样 |
|---|---|---|
| **① 启动与菜单链路** | 启动画面 / Logo → 主菜单 → 创角（或选角）→ 读条进图 | **没有完整游戏是"打开就直接站在游戏场景里"的** —— 一眼假 |
| **② 首场景 / 首关卡完整版** | 真素材 + 真动画 + 真操作（手感对） + 真 UI + 真音效 + 完整闭环 | 能跑不能玩 |
| **③ 游戏内流程** | 暂停菜单 / 设置 / 结算 / 回主菜单 / 退出 | 进去出不来 |

菜单与流程编排的写法（状态机 + 面板 + 场景三元组）见 **`patterns/client/app-flow.md`**。

**判定口径（硬）**：

- **完整版**：**从启动到进图的链路走通**（启动画面 → 主菜单 → 创角/选角 → 读条进图）+ 点进去能玩一整轮（操作 → 战斗/交互 → 反馈 → 结算/循环/回菜单），视觉/听觉/手感都像那么回事（对照 §0.0 参考规格逐项打勾）；
- **不是完整版**：直接进游戏场景 / 菜单点了没反应 / 能跑但"没动画/没音效/操作别扭/UI 是调试字/场景是白盒/手感没调" ⇒ **半成品，不许交付**；
- **允许花很久**（不设时长上限），**但必须多轮实测**；确定做不到的部分要当场说清"为什么做不到"，
  而不是偷偷降级成最小可用。
- **完成度不许分阶段**：动画、操作（相机+移动）、场景内容、UI/HUD 属**阶段 1 必交**，不许推到阶段 2，更不许以"代码留钩子 + 清单待替换"结案；
- 若确实不按整款游戏报价，要说清差别在**内容量**，而不是"先给你个假的看看"。

### 0.1 交付纪律：**三段一次做完，且全程只在"做完"时汇报一次**（硬规则）

**「一键出游戏」= ① 启动/菜单/创角链路 + ② 首场景全部内容 + ③ 游戏内流程，一次性交付。不存在"阶段 1 = 骨架 / 阶段 2 = 补内容"这种切法。**

> **⏱ 不许砍范围（硬性）：时间 / token / 规模 / agent 数量都不是理由。** 不许因为"内容多 / 耗时长 / 步骤多 / 要拆很多 agent"就砍范围、分步做、中途交差，也不许把"剩下的下次再做"写进交付说明。**起手就把 ①②③ 全部内容 + §0.0c 原版系统清单列入待办，一直做到全部完成再说话。** 允许做很久；**宁可不交付，也不交半成品**。（物理上限靠换手接力跨过 —— 见 `SKILL.md`「谁来做」。）

```text
本轮（一次性做完）：**三段全部内容**
  ① 启动与菜单链路
  · 启动画面 / 主菜单（开始 / 继续 / 设置 / 退出；联机加登录 / 注册）
  · 创角（或选角）→ 读条进图（真进度）
  ② 首场景的**全部内容**
  · 场景与地图（**引擎烘焙** Clover/地图烘焙 + 客户端同源碰撞）
  · 操作（输入 / 移动 / 第三人称相机与遮挡避障）
  · 动画（idle/run/walk/attack/hit/death，全部接线）
  · UI（HUD：血条 / 目标 / 交互提示 / 按钮，真面板）
  · 战斗闭环（攻击 → 伤害 → 受击表现 → 死亡 → 复活）
  · 音效（脚步 / 挥砍 / 命中 / UI / 进图）
  · 复活与基础循环（打完能继续玩）
  · §0.0c 原版系统清单里的每一项（技能 / 背包 / NPC 对话 / 精英怪 / 随机地图 …）
  ③ 游戏内流程
  · 暂停菜单（继续 / 设置 / 回主菜单）/ 结算界面 / 退出 / 回主菜单后能再进一次
  · 分层分模块（见 reference/architecture.md，**交付前跑完 §4 的 7 项自检**）+ 自证 + 按类别取证（表现类 = 联络图）
       ↓
  一次**完整交付说明**（只有这一次汇报）
       ↓
下一轮 = **用户在看过成品之后提出的新内容**（更多关卡 / 角色 / 职业技能 / 系统…）
```

- **禁止**"先生成个能跑的骨架 → 停下来等用户确认 → 再补动画/音效"；
- **禁止**"做完一项汇报一次"（做一项报一次 = 违规）；过程中只在 ① **被阻塞、必须问用户** ② **全部做完** 这两种情况说话；
- 用户实测反馈不通过 → **改成他要的效果**（这属于返工，不算新一轮内容）；
- **禁止**把"分层分模块"当建议：一个系统一个模块、依赖单向、**App ≤ 200 行**、UI 不引用业务模块、网络只走 Net 门面（`reference/architecture.md`）。**交付前必须跑完 §4 的 7 项自检，并把数字写进交付说明**（App 行数 / 跨模块耦合命中数 / UI 引用业务模块命中数 / 业务直连网络命中数 / 裸事件名命中数 / **硬规则命中数** / **临时文件散落数**）—— **数据说话，不许只写一句"已分层"**。
- 三段（含 §0.0c 原版系统清单）的验收口径见本文件 §6；**没做到"全部内容"就不要交付**。

### 0.2 能力归属判定：先分清「引擎缺口」还是「业务产物」（四桶）

用户问「能不能做 XX」，或你要说明「缺什么」时，**必须先把缺的东西归到下面四桶之一**。否则极易把业务产物误报成"引擎不支持"，让用户以为要改引擎 —— **这是最伤信任的误报**。

| 桶 | 含义 | 谁写 | 例子 |
|---|---|
---|---|
| **A 引擎已实现** | 拿来直接用 | 引擎 | AOI（**三维球体视野，默认开**）/ 寻路（2D 网格 + **3D 分层**）/ 碰撞（2D 宽相 + **3D 宽相与立体弹道**）/ 物理 / 伤害内核 / Buff / 帧同步 / 房间生命周期 / 数据层 / 配表 / 单机启动 / **地图管线**（Unity 烘焙 → CloverMap 二进制 → 服务端 `NavGrid3`+`Collider3` / 客户端 `Game.Map`） |
| **B 引擎显式留了口** | 引擎代码里有**注册位 / 接口**，且文档写明"业务实现" | 业务（引擎在等） | **`room.Kernel`**（状态同步内核；**原 demo 范例 `function_test/state_room.go` 已随 `clover-demo-a` 一起删除，需业务自行实现**）—— **全仓仅此一项** |
| **C 业务自己写** | 引擎**不提供专门支持、也不需要提供**；业务用 A 类能力 + 通用 API（含 **Unity 原生 API**）自行实现 | 业务 | **回合出手序 / 匹配 / 开局 / 房间列表 / AOE 形状 / 命中闪避 / 属性聚合 / 房间人数上限**、背包 / 卡牌 / 抽卡 / 任务 / 邮件 / 商城、平台 SDK、**分包**、UI、数值、**客户端 3D 表现与操作**、**本地预测解算**（半径采样 / 分轴滑墙 / 扫掠细分 —— 引擎只给"这一格能不能走"，手感归业务） |
| **D 必须改引擎** | 业务绕不开 | 引擎 | **当前为空。** 原唯一项「服务端立体空间」**已实现**：AOI 三维球体视野、`collide.Grid3` 三维宽相、`SweepCCD`/`Raycast` 立体弹道与视线、`collide.NavGrid3` 分层寻路、`mover` 重力/跳跃/飞行 + 高度场落地、跨图/跨机迁移带高度。**客户端 3D 不算 D** |

规则：

- **B 与 C 的唯一区别 = 引擎有没有替你留一个「注册位」**：`room.Kernel` 是引擎声明好的接口（填实现即可，外壳全归引擎）；而**回合出手序 / AOE / 匹配**这类，引擎**既没留口也不需要留**，业务用 `combat` / `QueryRegion` / `Timer` / 数据层自己搭。**两者都不改引擎。**
- **A / B / C 一律不改引擎**：不许说成"引擎不支持"（C 桶最容易被误报），也不许把 C 说成"引擎留了口"。
- **只有 D 桶**可以回复"需要改引擎"，且必须先说清量级、拿到用户确认再开工。**当前 D 桶为空**，所以对任何玩法都应先默认「引擎够用」，把结论落到 B/C 桶上。
- 拿不准归属时用一把尺子：**「数据层 + `Timer` + 房间域 + etcd 发现」够不够搭出来？** 够搭 = C（业务）；只差一个引擎**已声明的接口** = B；接口都没有且业务绕不开 = D。
- 典型误判（**不许再犯**）：把「回合出手序 / 匹配 / 状态同步内核 / 命中闪避 / AOE / 场景 tick / 属性聚合」说成引擎缺口；把「背包 / 卡牌 / 抽卡 / 任务 / 平台 SDK / 分包」说成引擎不支持；把「**客户端 3D 相机 / 角色控制 / 物理 / 射线**」说成引擎缺口 —— 业务在自己的 Unity 工程里可直接用 Unity 原生组件与 API，客户端 3D 属 **C 桶**。**立体空间（多层地形 / 飞行 / 立体弹道）也不再是引擎缺口** —— 引擎已提供三维视野、三维碰撞与分层寻路；业务要做的只是**建图**（把 Unity 场景烘焙成 `Grid3` / `NavGrid3`），属 C 桶。
- 支持度只给二值：**✅ = D 桶为空（引擎够用）**、**❌ = D 桶非空（需改引擎）**——按当前状态，**一律 ✅**。不要用"骨架支持 / 部分支持"这类中间档，也**不要把量产规模结论混进"首场景支持度"**里（首场景与量产分表评，见 `game生成.md` §1 / §1.1）。
- 引擎侧小瑕疵（`SceneBeat` 不自动驱动、`pathfinding.FindPath` 只支持单单位）**不属 D 桶**（业务可绕开），备忘见 `game生成.md` §4.2。（原列表里的 `Result.Hit` 硬编码 `true` 与 `frame.Config` 无人数上限**已修**：现为 `HitStrategy` 与 `MaxPlayers`。）
- **客户端本地预测 / 回滚由业务自己做**（引擎只提供「服务端权威 + 客户端插值」，见 `clover-client-unity-engine-index.md` §3.1）—— 属 **C 桶**，**不是引擎缺口**，引擎不补。
- 归属判定与逐游戏证据表见仓库根 **`game生成.md`**。

## 1.5 前置：先判定形态，再决定「要不要服务器」（**顺序不许反**）

### 第 1 步：判定形态（**这一步不做完，后面一个字都别写**）

规则见 `SKILL.md::闸门 0`。落地到本 SOP 就是**三个问题**，按顺序问自己：

| # | 问题 | 怎么看 |
|---|---|---|
| 1 | **原版这款游戏是什么形态？** | **联网搜一轮**（`<游戏名> single player or multiplayer` / `<游戏名> 是单机还是网游`）—— 这是**第一依据** |
| 2 | **用户这一轮明确要求联机了吗？** | 出现"联机 / 多人 / 服务器 / 对战 / 排行榜 / 房间 / 匹配 / 联机版"才算 |
| 3 | **联网方式是什么？**（仅形态为联机时才需要） | 权威服务器 / 局域网 / P2P / 大厅+房间 / 直连 IP |

**判定规则**：

- 原版是**单机** → **做单机**。不建 `server/`、不调 `CloverNet.Init`、**不查服务器环境**、
  不跑 `env.exe`；交付说明**首行**标注「单机版」，其余交付标准（打开即跑、动画/音效/UI/流程全在）**一点不降**。
- 原版**同时有单机与联机两种模式**（如暗黑破坏神 2）→ **默认做单机模式**（它是原版的一等公民，
  且"打开就能玩"是本 SOP 的验收底线）；**用户点名要联机**才做联机。
- 原版是**纯网游**（MMO / 对战竞技 / 大逃杀）→ 做联服，此时才走第 2 步。
- **拿不准**：先搜；搜完仍拿不准，**问用户一句话**。
  ⛔ **禁止"一边拿不准、一边反复探测本地服务器环境"** —— 用户对此的原话是
  「做个单机一直测网络，是不是有病」。**反复自检 = 已经判错方向的信号。**

> **判定结果必须写进** `策划/策划案/{A}参考规格.md` 顶部的「**形态**」一节，
> 并且**只判一次**：全程照它执行，中途不许反复改变、不许反复自检。

### 第 2 步：只有**形态为联机**时，才做服务器环境自检

**触发条件（两条同时满足）**：① 第 1 步判定为联机；② 马上要写 C2S 回路代码。**单机任务整段跳过。**

**触发（联服场景）**：写任何代码之前先确认服务器环境，不许写完再说。

```bash
# 1) 环境在不在 / 组件就绪没
clover-server-tools/windows-env/core/env.exe info
# 2) 没起就起
clover-server-tools/windows-env/core/env.exe start
```

| 检查结果 | 处理 |
|---|---|
| env.exe 在，etcd/nats/redis/mysql 全就绪 | 正常开工 |
| env.exe 在，组件未起 | `env.exe start` 后 `info` 复检 |
| 组件缺失（未下载） | 按 `reference/server-env.md` §2 让**用户**下载，AI 只做校验/放置/启动 |
| `windows-env/` 整个不存在 | 环境未安装 → **停下来告诉用户**，不许绕过 |

**铁律：不许静默降级成"单机 / 离线 / 模拟模式"。** 以下行为一律算交付失败：

- 悄悄把联服玩法改成"AI 随机出拳 / 本地算结果"；
- 客户端加"服务器不可用就自动切模拟模式"兜底；
- 注释掉 `server.yaml` 里的 mysql/etcd/nats 依赖来"简化"配置；
- 用户点名的模式（如匹配对战）只留空壳，回一句"框架已预留，暂未实现"。

环境不可用时先把情况摆给用户，**等回答再动手**，三选一：

1. 装 / 起环境（AI 协助校验、放置、启动，下载交给用户）；
2. 用户**明确同意**做离线版 → 才降级，且必须：联服代码留 TODO 不删、交付说明首行标注「⚠️ 离线版：本地无服务器环境，联服流程未验证」、`client/资源欠缺清单.md` 登记"联服验证"为待办；
3. 只交服务端代码（`go build` 过）+ 编译说明，不起服。

## 3. 第 1 步：切分「逻辑」与「资源」

开工前在回复里列一张两栏清单，**逻辑 = AI 负责；资源 = AI 优先找现成素材并接入（能下就下），找不到才占位**：

| 逻辑层（AI 全做，零资源） | 资源层（AI 负责**接入真资源**） |
|---|---|
| 服务端：消息号 / schema / handler / 结算 / 广播 | 卡牌/棋子/角色 Sprite 与模型 → **先穷尽参考游戏 A 自己的素材**（闸门 3），拿不到再降级 |
| 客户端：UI 结构、按钮行为、网络收发、状态流转 | 按钮/面板美术、背景图 → 同上 |
| 表现：状态切换、胜负展示、数值刷新 | **动画 Clip（必须接线）+ 音效 BGM + 特效** → 优先随素材包自带的动画/音效 |
| 操作：相机 + 移动 + 输入（第三人称/第一人称） | 配表数据（策划后续填 / 调数值） |

> 右侧栏的目标是"**接进去能用**"，不是"登记进清单等用户换"。占位只出现在"该资源到处都下不到"这一种情况下，且必须在回复首行高亮。

## 4. 第 2 步：逻辑先行，资源分级获取（**先穷尽 A 自己的素材** → 再同类 → 再兜底 → 再自产 → 最后占位）

### 4.0 资源从哪来（**硬闸门：必须先用 A 自己的素材**）

做「一键出 XX 游戏」时，美术/音效/模型**不是一律占位**。交付目标是**成品级**；
**本项目非商用 ⇒ 不设许可门槛，能下到合适的就直接用**。

> ### ⛔ 硬闸门（违反即交付失败）：级 ① 穷尽之前，禁止碰通用兜底素材
>
> **用户点名了 A ⇒ 目标就是"一眼认得出这是 A"。素材是这件事权重最大的项。**
>
> 1. **级 ①（A 自己的素材）是唯一首选，必须"穷尽"** —— 量化定义：
>    **≥ 4 轮**不同关键词（中英各半）× **≥ 3 类站点** × 换过**格式/打包方式**。
> 2. **穷尽之前，禁止下载 / 禁止接入任何通用兜底素材**（KayKit / Quaternius / Kenney / 内置几何体…）。
>    ⛔ **不许拿"先做起来 / 别停工 / 能用就用，否则会停工"当跳级理由** ——
>    这条曾经就是漏洞：它让 AI 第一轮就跳去用通用素材，用户直接质问
>    「skill 不是让你先找相关的素材吗？你怎么默认使用通用素材了！」。
> 3. **调研必须落盘 `策划/素材调研.md`**（每轮：关键词 / 站点 / 拿到什么 / 为什么不可用）。
>    **没有这份文件 = 闸门未通过，不许开始接资源。**
> 4. **A 的素材要"用户本机游戏文件 / 登录 / 会员 / 付费 / 点按钮"→ 走级 ④：先给用户清单并等用户**，
>    **不许自己跳过 ①**。Blizzard 系（MPQ/CASC）就属此类：解包工具公开，**本体文件只有用户有**。
> 5. **级 ③ 兜底素材只有 ①② 都真的做不到时才允许**，且必须：① `素材调研.md` 写清原因；
>    ② **交付说明首行**高亮「⚠️ 未使用 A 的素材」；③ `资源欠缺清单.md` 登记"待换"。
> 6. **禁止把"下不动"说成"没有"**：换镜像 / Gitee 同名仓 / 压缩包直链 / 论坛附件，都试过才算数。

|---|---|---|
| **① 用户点名的游戏 A 自己的素材（★ 唯一首选，必须穷尽）** | 原版 / 同源 / 复刻 / 官方 SDK / mod 工具 / 社区提取 / rip。关键词矩阵（**≥ 4 轮，中英各半**）：`<A> assets pack`、`<A> sprite sheet`、`<A> ripped assets`、`<A> extracted textures`、`<A> clone/remake open source`、`<A> mod tools`、`<A> resource extractor`、`<A> 素材 提取 解包 复刻 图集`。站点矩阵（**≥ 3 类**）：GitHub / Gitee 与镜像 / spriters-resource / 论坛（贴吧 NGA 3DM 游侠）/ CSDN 爱给 网盘直链 | 玩家一眼认得出。**直接用**（含 rip / 来源不明，非商用不设门槛），记一行来源。**拿不到就先去问用户（级 ④），不许自己跳过** |

### 4.1 服务端

- **零资源**，完整实现 + `go build` 过 + `env.exe start` 后能起服。
- 全流程走 `patterns/{datadef,handler,mount,crossnode,signup-login}.md`，消息号段见 `reference/conventions.md`。
- **配表（有"会被策划改 / 会随版本增长"的数值时必做）**：游戏配表能力是现成的，三步闭环 —— ① AI 写源表 txt → ② `-pack` 反出 xlsx 交策划用 Excel 改 → ③ 打表出 tsv + 强类型代码。完整规则见 **`patterns/table.md`**：
  - 源表放 `<项目>/策划/数值文档/<名>_<后缀>.txt`，**表名必须带 `_cs` / `_c` / `_s` 后缀**（否则整表静默跳过）；
  - 读表用产物自带的强类型访问器（服务端 `table.Default.Xxx.Get(id)` / 客户端 `Tables.Default.Xxx.Get(id)`）；
  - **禁止**把数值、掉率、关卡配置硬编码进 handler —— 那正是配表要消灭的东西。

### 4.2 客户端（★工程必须用 unity-cli 创建，再写代码）

**禁止**手写 `client/Assets/Scripts/...` 目录树来"假装"是 Unity 工程——没有 `Packages/`、`ProjectSettings/`、`.meta` 的目录 Unity 根本打不开，那不是工程。

正确顺序（详见 `scaffold/new-project.md` §2）：

```bash
# 1) 自检并确认 Unity 6（6000.x）；没装 CLI 就自动装（见 reference/unity-cli.md）
unity --version
unity editors list --format json

# 2) 创建真工程（模板 id 先查，不要猜；工程名固定 "client"、--path 传项目根）
unity templates list --editor 6000.0.47f1 --format json
unity projects create "client" --path "clover-{项目名}" \
  --editor-version 6000.0.47f1 --template com.unity.template.3d

# 3) 接入 Clover 引擎包：Packages/manifest.json 加一行
#    "com.clover.unity-engine": "file:<ENGINE_CLIENT_PATH>"
```

工程建好后再往 `Assets/` 里写业务脚本。**写任何网络代码之前，必须先创建 Def/ 目录**（见下面目录结构）：

1. **先建 `Assets/Scripts/Def/MsgDef.cs`**：定义业务消息号（镜像服务端 `server/game/def/{msg,reply,push}.go`）
2. **再建 `Assets/Scripts/Def/ProtoDef.cs`**：定义协议结构体（Request / Reply / Notify DTO）
3. **然后才写 Network / UI 等业务代码**：在业务代码里引用 `MsgDef.Xxx` 而非硬编码消息号

然后是其他业务脚本（**成品级要求**）：

- **启动 / 菜单链路要做（硬约束）** —— 启动画面 → 主菜单 → 创角（或选角）→ 读条进图 → 暂停 → 回主菜单；**禁止**把游戏场景当应用入口。写法见 **`patterns/client/app-flow.md`**（`Game.Fsm` 站点状态机 + `Game.UI` 面板 + `Game.Scene.Load` 读条 + 回菜单清场清单），菜单面板同样放 `Resources/UI/{类名}`。
- **UI/HUD 要做真面板**：走 `Game.UI.Open<T>()` + 预制体 `Resources/UI/{类名}`（AI 用 Editor 脚本生成预制体，用户之后可在 Editor 里改样式）；**禁止**用 `OnGUI` 调试文字当交付；按钮用 `EventSystem`（`CloverInput.Init()` 已保证）。
- 资源引用**全部收敛到资源常量表 / 集中路径**，禁止散落路径字面量；后续替换 = 换文件，不碰逻辑。
- **有可操控角色就必须做操作（硬约束）** —— 第三人称/第一人称**相机 + 移动**。三条实测铁律：
  1. **输入走引擎 `Game.Input`**（`State.MoveDirection` / `GetKeyDown(GameKey.X)` / `MouseDelta`）—— 引擎自动探测输入后端；**直连 `Keyboard.current` 在旧后端工程下会拿到 null ⇒ WASD 完全不响应**；
  2. **自己的位置必须本地预测**：**绝不**用服务端插值位置逐帧覆盖自己（否则手感 = 网络延迟，服务端拒绝/丢包时表现为"按键不动"）；服务端权威位置只用于**校正**（小误差忽略、大误差拉回）；
  3. 相机：引擎的 `Game.Camera.Follow` 是**"锁 Z 的简单跟随"**（无环绕、无防穿墙）⇒ 第三人称请**业务自写**环绕相机（属 C 桶；只要**不调用** `Follow`，引擎就不会抢相机 Transform）。
- **动画必须接线（硬约束）**：素材自带动画 → 用 Editor 脚本生成 `AnimatorController` → `Game.Anim.CreateAnimator(modelGo, controller)` → `SetFloat("Speed")` / `SetTrigger("Attack")` 驱动状态。（`AnimatorController` 是 Editor 资源类型，运行时建不出来；生成脚本记得 `using UnityEditor.Animations`。）
- **引擎模块要显式初始化**：`Game.Res` **不会**随 `CloverPresentation` 自动挂载，必须业务调 `CloverRes.Init(root)`；漏了它 `Game.Res` 恒为 null ⇒ **模型永远加载不出来（只剩占位体）且会在加载点抛 NullReferenceException 打断进图流程**（实测踩过，见 §8 的验收自证）。

**必须创建的文件夹结构**（在 `Assets/` 下）：

```text
Assets/
├── Resources/                # 占位资源文件夹（必须创建）
│   ├── Placeholder/          # 占位图片文件夹（必须创建）
│   │   ├── placeholder_64x64.png   # 默认 64x64 像素占位图
│   │   ├── placeholder_128x128.png # 可选 128x128 像素占位图
│   │   └── placeholder_256x256.png # 可选 256x256 像素占位图
│   ├── Sound/SFX/                # 占位音效文件夹（可选）
│   └── Models/               # 占位模型文件夹（可选）
├── Scripts/
│   ├── Def/                 # ★ 业务消息号 + 协议（必须，镜像 server/game/def）
│   │   ├── MsgDef.cs        # 消息号常量（唯一定义处）
│   │   └── ProtoDef.cs      # 协议结构体
│   ├── Core/
│   ├── Network/
│   ├── UI/
│   └── Resources/            # 资源管理脚本
└── Configs/
```

**占位图片生成规则**：

- 默认生成 64x64 像素的 PNG 占位图（纯色块，如灰色或红色），**文件必须实际存在**（不能只有代码引用）；如用户指定尺寸，按用户要求生成；
- 文件夹结构必须创建完整。

**场景创建与脚本挂载（AI 自己做，不许丢给用户）**：

- 建场景（如 `Assets/Scenes/Main.unity`）并保存，加进 Build Settings
- 建挂载点 GameObject（如 `Bootstrap` / `GameRoot`），`AddComponent` 挂上业务入口脚本
- `unity console tail --format json` 确认无编译错误
- **交付标准 = 用户打开工程点 Play 就能跑**；交付说明里不许出现"请用户手动创建物体并挂载脚本"
- 做法见 `reference/unity-cli.md` §7

### 4.3 占位规则（AI 不许因缺美术而停手）

| 资源类型 | 占位方式（工程内自带/零成本） | 尺寸要求 |
|---|---|---|
| 图片/图标/Sprite | 单色 1x1 占位图（若引擎无内置可让 AI 生成一个 `placeholder.png`），或 Image 用纯色块 | 默认 64x64 像素；如用户指定尺寸，按用户要求生成 |
| UI 布局 | 真 uGUI 布局（HUD 信息区/按钮/血条），可用临时配色 | 分辨率适配默认 1920x1080 |
| 音效/BGM | **优先接入真音频**（素材包自带 / CC0 音效库）；实在没有才退化为 `Play(name)` 钩子 + 日志 `[SOUND] name`（并在回复首行高亮） | 无 |
| **动画** | **必须接线**：素材自带动画 → `AnimatorController`（idle/run/attack/hit/death 状态 + 参数）+ `Game.Anim`。**禁止**把"打日志"当动画交付 | 无 |
| 3D 模型 | 能用真素材就用真素材；确实没有才用内置 `Cube`/`Capsule`/`Sphere`（**成品级交付不该出现**） | 默认 1x1x1 单位 |
| 特效 | 空占位（代码留 Trigger 点） | 无 |

**占位图尺寸的说明**：

- Unity uGUI 的 Image 组件默认 Simple 模式会自动拉伸到 RectTransform 尺寸，所以占位图像素大小不影响占位显示；
- 但标注尺寸的目的是**方便用户替换时对齐**：真实美术资源需要匹配目标尺寸，否则会出现比例失调或清晰度不一致；
- 对 Sliced/Tiled 模式的 UI、游戏内 Sprite（非 UI）、图标/头像等固定比例资源，尺寸标注尤为重要；资源替换清单中必须标注每个资源的目标尺寸。

> 任何"等美术给图才能写"的依赖都必须在这一层被消解成"钩子 + 占位"。**可玩性优先于美术。**
