# 范式：配表（AI 产源表 → 策划改 → 打表出代码）

## 何时该用配表

| 用配表 | 不用配表 |
| --- | --- |
| 会被**非程序**改的数值（怪物属性、道具、关卡、掉落） | 纯逻辑常量（协议号、状态枚举） |
| 行数会增长的数据（道具表、任务表、成就表） | 一两行且永不改的配置 |
| **同质化的业务配置**（技能伤害 / 等级与经验 / 怪物属性 / 地图表 / 掉落 / 商店 / 成就） | 单条一次性逻辑（不是"同一套字段重复很多行"） |
| 客户端与服务端**都要**读的数据 | 只有一端用的临时数据 |

**一句话判据**：这张表会不会被别人改？会 → 配表。
**第二条判据（同质化，同样是硬性的）**：同一套字段要重复很多行（20 个技能 / 60 级 / 30 张地图）→ **不管谁改，一律配表**；
反过来，**代码里出现成排的同质化常量、大 `switch`、大 `map` 字面量 = 该抽表了**（`if level == 3 { hp = 250 }` 这类写法属违规）。

---

## 三步闭环

```text
① AI 写源表 txt ──[table -pack]──▶ ② xlsx（策划用 Excel 改）
                                        │
                    ③ [table -config] ─┘──▶ tsv + 强类型代码（Go / C#）
```

AI 只能产出文本、生成不了 xlsx，所以约定「源表 txt」作为中间格式；
它的布局与 xlsx **完全一致**，只是用 tab 分隔。

---

## 第一步：写源表（AI 直接产出）

文件放 **`<项目>/策划/数值文档/<名>_<后缀>.txt`**，**tab 分隔**：

> **目录约定**：配表全部放 `<项目>/策划/数值文档/`，玩法/数值策划案放 `<项目>/策划/策划案/`，两者分开。
> 打表 config 的 `planning_dir` 必须指向 `策划/数值文档/`；**该目录是单层扫描、不递归**，所以源表 txt 和
> 生成的 xlsx 都平铺在这一层，**不要再往下套子目录**（套了就扫不到）。

```text
name	hp	atk
int	int	float32
cs	cs	c
名字	生命	攻击
1	100	10.5
2	200	20.0
```

| 行 | 内容 | 规则 |
| --- | --- | --- |
| 1 | 字段名 | 英文；**空 = 整列无效** |
| 2 | 类型 | 见下方类型表；**写错 = 整列无效** |
| 3 | 端标记 | `c` 仅客户端 / `s` 仅服务器 / `cs` 两端 / 空 = 按配置 `default_side` |
| 4 | 注释 | 中文说明，会进生成代码的注释 |
| 5+ | 数据 | **第一列必须非空**（主键）；主键空的行跳过；主键以 `#` 开头的行按注释跳过 |

### 文件名后缀决定去向（**硬规则**）

| 文件名 | 逻辑名 | 生成到 |
| --- | --- | --- |
| `hero_cs.txt` | `hero` | 客户端 + 服务器 |
| `hero_c.txt` | `hero` | 仅客户端 |
| `hero_s.txt` | `hero` | 仅服务器 |
| `hero.txt` / `hero_.txt` | — | **整个表被跳过，什么都不生成** |

> ⚠️ **不带 `_c` / `_s` / `_cs` 后缀 = 静默跳过**。AI 天然会取名叫 `hero`，
> 结果打表工具一个文件都不产出，而人还以为是工具坏了。

### 支持的类型

| 类型 | 说明 | 单元格写法 |
| --- | --- | --- |
| `int` / `int32` / `int64` | 整数 | `100` |
| `float32` / `float64` | 浮点 | `10.5` |
| `string` | 字符串 | 任意文本 |
| `map[int]int` | 键值对 | 对之间 `\|`，kv 之间 `;` → `1;10\|2;20` |
| `map[int]string` | 同上、值为串 | `1;剑\|2;盾` |
| `[]int` | 整数数组 | `7;8;9` |
| `[]string` | 字符串数组 | `剑;盾;药` |
| `vector3` | 三维向量 | `5;5;0` 或 `100,100,1` |

别名也认：`map[int,int]`、`int[]`、`slice[string]`、`vec3` 等。

## 第二步：打包成 xlsx（交给策划）

```bash
cd table/core
go run ./cmd/table -pack -config config.yaml -batch
```

| 参数 | 作用 |
| --- | --- |
| `-pack` | 反向：源表 `*.txt` → `*.xlsx` |
| `-batch` | 非交互（不选配置、不等回车、失败退出码非 0）；**AI / 脚本调用必须带** |
| `-force` | 覆盖已存在的 xlsx。**会冲掉策划的编辑，慎用** |

**默认不覆盖**已存在的 xlsx——那通常是策划改过的成品。

---

## 第三步：打表出 tsv + 代码

```bash
cd table/core
go run ./cmd/table -config config.yaml -batch
```

产物结构：

```text
server_dir/
├── <table>.go        首次生成，不覆盖（业务逻辑写这里）
├── registry.go       每次覆盖（勿手改）
├── base/             每次覆盖
└── tsv/<table>.tsv   每次覆盖
client_dir/           结构对称，base 子目录为大写 Base/（C# 约定）
```

## 代码侧怎么读

**服务端（Go）**

```go
tables := table.NewTables()
tables.LoadAll("tsv")
hp := table.Default.Hero.Get(1001)   // 强类型访问，无需手解析
```

**客户端（C#）**

```csharp
// ① 加载（引擎侧加载器，E-core-11）—— 成功返回 null、失败返回可定位错误串（⛔ 不抛）
string err = CloverEngine.CloverTable.LoadAll(Application.streamingAssetsPath, Application.dataPath);
if (err != null) Game.Logger.Error("Table", err);

// ② 取行：两条路都在，用途不同
var row = CloverEngine.CloverTable.Get<HeroRow>("Hero", 1001);   // 引擎读取器（反射填 public 字段）
var row2 = Tables.Default.Hero.Get(1001);                        // 打表产物自带的强类型访问器（零反射）
```

> `Game.Table` 是**运行时**读取接口；`CloverEngine.CloverTable` 是**读打表产物**的加载器（E-core-11：
> 目录解析 / 逐 tsv 读取 / 可定位错误串 / 按主键强类型取行 —— 引擎旧入口 `CloverData.InitDataTable`
> 要求行类实现 `IDataRow`、**读不了打表产物**）；`Tables.Default.*` 是**打表产物自带的**强类型访问器
> （有 `Get(id)` / `All()`，`All()` 这类枚举能力引擎契约里没有）。
> ⇒ **加载一律用 `CloverTable.LoadAll`**，⛔ 别每个项目自己再写一份"找目录 / 读 tsv / 建索引"的加载器。

## 硬规则（违反会静默失败，务必逐条核对）

1. **表名必须带 `_c` / `_s` / `_cs` 后缀** —— 否则整表静默跳过。
2. **第一列是主键且必须非空** —— 主键为空的行会被跳过，常被误判成"数据丢了"。
3. **类型必须用上面列出的** —— 写 `bool` / `json` / `dict` 等会让**该列无效**（不报错、静默丢列）。
4. **改了表结构要重跑打表** —— 否则代码与数据不一致。
5. **`base/*` 与 `registry.*` 每次覆盖**，不要手改；业务逻辑写在上层 `<table>.go` / `<table>.cs`。
6. **`-pack` 默认不覆盖 xlsx** —— 想用源表覆盖策划的编辑必须显式 `-force`，用前先确认。
7. **业务功能里的同质化配置必须抽表** —— 见 `SKILL.md`「数据一律走配表（硬约束）」；把成排数值硬编码进业务代码（`if level == 3 { hp = 250 }`）= 违规。

## AI 交付配表时的检查清单

- [ ] 源表放在 `<项目>/策划/数值文档/`（`planning_dir` 指向这一层，且没有往下再套子目录）
- [ ] 表名后缀正确（`_cs` / `_c` / `_s`）
- [ ] 4 行表头齐全（字段名 / 类型 / 端标记 / 注释）
- [ ] 类型都在支持列表内
- [ ] 主键列无空值、无重复
- [ ] 复合类型单元格分隔符正确（`|` 与 `;`）
- [ ] 跑过 `-pack`（产出 xlsx）与 `-config`（产出 tsv + 代码），且无"跳过"提示
- [ ] 业务功能里的同质化配置**已抽表**：代码里没有成排硬编码常量 / 大 `switch` / 大 `map` 字面量

## xlsx 产出规范（**硬约束**）

> 规则原文在 `SKILL.md::配表 xlsx 产出规范`。⚠️ **本节每条都带源码出处** ——
> 涉及打表工具行为的地方 ⛔ **不许凭推断补**（宁可写"未查证"，也不许写"看起来应该是…"）。

| 要求 | 说明 |
| --- | --- |
| **文件名用中文** | **一个功能一个 xlsx**，文件名用中文：`战斗.xlsx`、`技能.xlsx`；⛔ **不许** `skill_cs.xlsx` 这种"英文名 + 后缀代码" |
| **页签英文，且必须带后缀** | 一个 xlsx 内多个页签，**页签名 = 表名（含 `_c` / `_s` / `_cs` 后缀）**：`skill_cs` / `monster_cs` / `drop_cs`。⛔ **不许译成中文、不许改页签名、⛔ 不许去掉后缀** |
| **一个功能一张表** | 同一功能的多个页签汇总进同一个 xlsx（例「战斗」= `skill_cs` + `damage_cs` + `buff_cs` 三页签），**只产出一个 xlsx** |
| **⛔ 不许一表一文件** | 每个源表 txt 各产一个 xlsx = 违规；策划改起来要开一堆文件 |

### 为什么"页签名必须带后缀"（去掉就静默消失）

打表工具**遍历 xlsx 里的每个 sheet、用「sheet 名」当表名**，**完全不看文件名**：

- `core/internal/sheet/xlsx.go:17-22` —— `for _, name := range f.GetSheetList()` / `sh := &Sheet{Name: name}`；
- 表名后缀决定去向（`table/README.md` §表名后缀）：`hero_cs` → 客户端 + 服务器；
  `hero_c` / `hero_s` → 单侧；**`hero` / `hero_`（不带后缀）→ 整表被跳过，什么都不生成**；
- ⇒ **页签名写成 `skill` = 那张表静默消失**，而人还以为是工具坏了。

**后缀在哪些地方会被剥离**：只在**生成产物的文件名与标识符**里 ——
表名 `demo_cs` → 逻辑名 `demo` → 生成 `base/base_demo.go`、`demo.go`、`tsv/demo.tsv`，
代码里的类型是 `BaseDemoRow` / `BaseDemoTable` / `DemoTable`
（产出实证：`产出/服务器/**`；命名规则见 `table/README.md` §生成代码示例）。
⇒ **策划 xlsx 的页签名一律保留后缀**（工具据此定表名）；
**xlsx 的文件名工具根本不读**，只需满足"中文名 + 一个功能一张"。

### `-pack` 产出什么（以及为什么还要整理一步）

`-pack` 是**反向**操作（源表 txt → xlsx）。它的实际行为（出处逐条）：

| 项 | 行为 | 出处 |
|---|---|---|
| 产出 xlsx 文件名 | = 源表 txt 同名（`skill_cs.txt` → `skill_cs.xlsx`） | `core/internal/pack/pack.go:62` |
| 产出 sheet 名 | = 源表文件名去 `.txt` = **`skill_cs`（后缀保留）** | `core/internal/pack/pack.go:94` 与包注释 `:19-20` |
| 一个 xlsx 几个页签 | **一个**（每个源表各产一个 xlsx） | `core/internal/pack/pack.go:82` |

⇒ `-pack` 的产物**不满足**上面"文件名中文"与"一个功能一张表"两条，
**必须再做一步整理**：把同一功能的几个页签**合并进一个中文名 xlsx**。这一步 ⛔ **不能省**。

### 运行时实证（工具自己跑出来的）

`产出/对照表.tsv`（每次打表生成，记录每个产物来自哪个 xls 的哪个 sheet）：

```text
source_file	sheet
示例.xls	demo_cs
```

⇒ **sheet 名是 `demo_cs`（带后缀）**。这是排查"表被跳过"时最直接的一手证据。
