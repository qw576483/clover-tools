# 为什么上一个项目做了那么久（14 个时间黑洞）

> 记录方式：**现象 → 我当时的错 → 正确做法 → 如何提前预防**。
> 这些不是理论，是同一个项目里逐条发生的。**"删库重建"时照着这张表走，能把返工砍掉大半。**

---

## T1. 没先读引擎就写业务：漏了 `CloverRes.Init`，模型从头到尾没加载成功（★ 最贵）

- **现象**：客户端只显示胶囊体；"进去看不到角色"；后来还发现 `EnsureView` 抛 `NullReferenceException` 打断进图。
- **错在哪**：以为 `Game.Launch` 会把所有模块都挂上（表现域确实自动挂），**但资源域（`Game.Res`）必须业务显式 `CloverRes.Init(root)`**。
- **正确做法**：动手前先产出「模块挂载矩阵」：谁自动挂（Logger/Event/Timer/…/UI/Anim/Camera）、谁必须业务挂（`Res` / `Input` / `Net` / `Data`），并写成启动顺序。
- **预防**：`reference/engine-mental-model.md` §1 直接照抄启动顺序；第一件事就是"把资源加载起来并打日志证明"。

## T2. 把"骨架能跑"当成果交付 → 被骂四轮"半成品"

- **现象**：链路通了就交付（能登录、能进图、位置能同步），但**没有操作、没有相机、没有动画、UI 是 OnGUI 调试字**；而且**一打开就直接站在游戏场景里** —— 没有启动画面、没有主菜单、没有创角。
- **错在哪**：把"技术链路验证"误当成"交付"。用户要的是**和原版一模一样的完整成品**。
- **正确做法**：**三段一次交付** —— ① 启动/菜单/创角链路（启动画面 → 主菜单 → 创角/选角 → 读条进图）② 首场景全部内容（场景/操作/相机/动画/UI/战斗/音效/复活）③ 游戏内流程（暂停/结算/回主菜单）；再按 `patterns/game-demo.md` §0.0c 的**原版系统清单**逐项做完（技能/背包/NPC 对话/精英怪/随机地图…）。
- **预防**：`SKILL.md` 铁律 1/8/13/14；开工就把 §0.1 的清单贴在计划里逐项打勾，缺项不许交付；菜单链路照 `patterns/client/app-flow.md` 做。

## T3. 做一项汇报一次 → 用户暴怒

- **现象**：每完成一小步就发一段汇报。
- **正确做法**：只在 ① 被阻塞必须问用户 ② 全部做完 时说话；中间不播报进度。
- **预防**：`SKILL.md` 铁律 9。

## T4. 没有本地碰撞就做第三人称操作 → "被拽回来"的六环链条

- **现象**：往前走就被拽回原点；按 WASD 看着不动。
- **错在哪**：客户端**完全没有碰撞**（连角色胶囊的 collider 都删了）→ 能穿墙/出图 → 服务端按地图拒绝 → 本地预测与服务端越差越大 → 最后被硬贴回。
- **正确做法（缺一不可）**：
  1. **同一份地图数据**给客户端（引擎烘焙器 `Clover/地图烘焙` 一次写 `Assets/MapData/` 与 `Assets/Resources/MapData/`）；
  2. 客户端**本地碰撞解算**：半径 8 向采样 + **分轴滑墙** + **扫掠细分（每段 ≤0.25m，防穿墙）**；
  3. 移动上行带**输入序号**，服务端拒绝时**回校正（带 ack）**，客户端「置权威值 + 丢弃已确认 + **回放未确认**」；
  4. **未进图/断线必须停发**（否则网关按 `unauthenticated` 拒绝并刷屏）。
- **预防**：照着写 `experience/3d-mmo-core-code/01-map-collision.cs` + `02-player-motor.cs` + `05-server-move-correction.go`；`patterns/client/3d-mmo-basics.md` §1/§2。

## T5. 相机凭直觉做 → "被遮挡时不会避障"

- **现象**：镜头穿墙、被墙挡住却愣着、拉近后角色糊满屏。
- **错在哪**：把 `MinDistance` 当**硬下限** → 被挡时机位仍留在墙里；只探一条射线 → 墙沿露缝。
- **正确做法**：多高度探针取最小 + **被挡允许拉到 0.2m** + `CheckSphere` 重叠兜底 + 收缩快/恢复慢 + 贴脸隐藏角色 + 机位不钻地。
- **预防**：照着写 `experience/3d-mmo-core-code/03-third-person-camera.cs`（**动手前先搜标准做法**，别凭直觉）。

## T6. 写死了"上帝视角"还不自知

- **现象**：相机 `position = 角色 + (0,18,-14)`、`Euler(55,0,0)` —— 用户："我进去是上帝视角，WASD 移动不了"。
- **正确做法**：有角色就**必须**第三人称（或第一人称）：pitch/FOV/距离/灵敏度一开始就定，场景初始机位也按第三人称摆。
- **预防**：`SKILL.md` 铁律 2（操作必做）；相机参数写进《参考规格》。

## T7. 重复登录 / 双实例 → 两个客户端同账号互相拽回

- **现象**：日志**每条出现两次**；服务端 3262 条未鉴权拒绝；位置来回跳。
- **错在哪**：① 场景里可能有**第二个 Bootstrap**（重复挂载）；② AI 后来加的重连逻辑**把首次登录也触发了一遍**（重复登录 ⇒ 旧连接绑定被顶掉却仍在发消息）。
- **正确做法**：`Awake` **单实例守卫**（多于 1 个自毁重复实例）；`LoginFlowAsync` 加**重入保护**；`Net.OnConnected` 只在"曾登录且本连接未绑定"时重登；**服务端还应有"同账号顶号"踢旧连接**。
- **预防**：`SKILL.md` 铁律 10 + `patterns/client/3d-mmo-basics.md` §4；服务端顶号列入待做。

## T8. 改了场景几何却没重导地图

- **现象**：客户端看得见墙、服务端不挡（或反过来）。
- **正确做法**：**几何变更 = 必须重新烘焙**（`Clover/地图烘焙`）；引擎烘焙器一次写服务端与客户端两份；把这条写进项目 `constraints.md`。
- **预防**：`experience/3d-mmo-playbook.md` §2 的"地图管线"步骤。

## T9. 靠"看着像"验收 → 用户看到的和 AI 以为的完全不同

- **现象**：AI 说"已经好了"，用户说"按 WASD 不动"。
- **正确做法**：**运行时自证**（`eval_file` 打印对象状态）+ **探针消息**（服务端权威答复）+ **截图**（含 HUD，PNG + 颜色多样性校验）+ **既有回归测试**。
- **预防**：`experience/verify-recipes.md` 全部照做；交付说明只能引用这些证据。

## T10. 引擎高频失败日志不降频 → 刷屏

- **现象**：一次断线刷 **3262 条** unauthenticated；另一处刷 **747 条** 回包失败。
- **正确做法**：高频路径"首次 + 每 1000 次"，精确次数交给 metrics；**改引擎要记账**（项目 `constraints.md` 里写 E 编号 + 回归方式）。
- **预防**：`SKILL.md` 日志硬约束 + `patterns/engine-fix.md`。

## T11. 低级几何错误（半格偏移 / 单位差异）靠探针才发现

- **现象**：模型被放到"格角点"而非"格中心" ⇒ 整图偏移半格 ⇒ 探针在建筑外沿判"可走"；第三方 FBX 单位不一致 ⇒ 100 倍大或半埋。
- **正确做法**：**一律量测**（实测 `Renderer.bounds` 反算缩放 + 按包围盒贴地 + 传格中心）；写完立刻用"点探针"验证几个关键点。
- **预防**：照着写 `experience/3d-mmo-core-code/06-editor-measure-place.cs`；`patterns/client/3d-mmo-basics.md` §2。

## T12. 没分层 → Bootstrap 上帝类

- **现象**：一个文件里同时有登录流程、实体视图创建/销毁、模型加载与归一化、动画装配、HUD 刷新、热键/探针、相机装配 —— 改一处要动同一文件，一次网络异常引发全功能瘫痪。
- **正确做法**：`Def / Core / Module(每系统一个) / UI / App` 五层，依赖单向，模块只暴露一个门面接口，**App ≤ 200 行**。
- **预防**：`reference/architecture.md`（含 **7 条**反耦合自检 grep）。

## T13. 工具用错：前台等 batch、被"项目已在编辑器中打开"卡住

- **现象**：`unity run ... -executeMethod` 长时间前台等待；工程被用户开着时报错退出；console 输出被压成一行难以解析。
- **正确做法**：**驱动正在运行的编辑器**（`unity status` → `eval_file` / `editor_play` / `capture_game_view` / `recompile_status`）；长任务后台起 + 轮询；console 先落盘再用正则取 `"message"`。
- **预防**：`reference/unity-cli.md` §8.1（本文件所有工具命令都来自那里）。

## 如果重来一次：推荐顺序（照着走能省 80% 返工）

```
0. 读 skill → 读 experience/ → 读 reference/engine-mental-model.md（挂载矩阵 + 启动顺序）
1. 环境自检（服务端依赖 + Unity 6 + CLI）→ 建工程 → **登记 Hub 并置顶**（让用户看得到）
2. 素材：按四级链找"目标游戏/同类游戏"的成套素材（**能 clone/直链就自己下，不设许可门槛**，记一行来源即可）
3. 服务端：消息号契约先冻结 → 起服 → 探针消息先可用
4. 地图管线：场景几何 → **引擎烘焙**（`Clover/地图烘焙`，一次写两份同源字节）→ 服务端 `mapdata.Load` + `ApplyTo` 日志确认 → 客户端 `Game.Map` 本地碰撞
5. 移动三件套：本地碰撞 + 预测/校正/回放 + 停发闸门（**一次全上**）
6. 相机：第三人称 + 遮挡避障（搬 core-code）
7. 动画：Editor 生成 AnimatorController → 运行时接 → 状态切换
8. HUD：真 uGUI 面板（预制体 + `Game.UI.Open<T>`）
9. 战斗闭环 + 音效（首场景必须包含）
10. 自证 + 截图 + 回归测试 → **参考游戏对照自审**（不像就改）→ **一次性完整交付说明**（含"参考游戏对照表"逐项打勾）
```

## T14. 只"跑通"就交付，从没和参考游戏比过 → 用户一句"不像"全面返工（★ 最贵之一）

- **现象**：功能全在、日志全绿、自证数字也对，但用户看一眼就说"这不像 XX" —— 菜单层级不对、HUD 位置不对、手感不对、配色不对。
- **错在哪**：把"功能验收"当成了"交付验收"。**交付的唯一标准是"像不像参考游戏"**，不是"跑不跑得通"；而且审查时只看了数字 / 日志，**没看画面**。
- **正确做法**：
  1. 动手前**必须有参考游戏名**；用户没给就**问用户要**（自己挑个同品类 = 必然返工，最贵的路径）；
  2. 准备 A 的参考截图 + 自己的**同角度**截图，一一配对；
  3. 逐项对照（菜单 / 创角 / HUD / 手感 / 表现 / 场景 / 音效 / 节奏），只允许写 `一致` / `不一致（差在哪）`；
  4. **只要有一项不一致 ⇒ 该版本不可交付** —— 改 → 重截 → 再对照，**循环到全部一致**。
- **预防**：`SKILL.md` 铁律 16 与「★ 交付前自审：像不像参考游戏」；`patterns/game-demo.md` §0.0 第 0 / 4 步；`reference/design-review.md` §3.6。
