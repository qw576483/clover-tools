# 项目级 skill 模板（建为 `<项目根>/tools/ai-skill/`）

> **用法**：建项目时在项目根创建 **`tools/ai-skill/` 目录**，按下面结构生成各册。
> 之后**每次新增对外可见的设施，都回来补一行** —— 这份文件的价值全在"保持更新"上，过期比没有更糟。
>
> **本目录由全局 `clover-engine` skill 在新建项目时生成 —— 是必做步骤，不是可选。**

## 0. 它是复合 skill，不是单文件

和全局 `clover-engine` skill 同构 —— **目录 + 入口 + 分册**：

```text
<项目根>/tools/ai-skill/
├── SKILL.md            # ★ 入口（必填，<100 行）：项目一句话 + 各册索引 + 硬规则
├── conventions.md      # ★ 本项目约定（必填）：消息号段分配、命名、目录边界
├── registry.md         # ★ 设施登记簿（必填，会最长）：消息号 / handler / 面板 / 管理器 / 通用函数 / 配表
├── constraints.md      # ★ 约束与风险（必填）：引擎/平台固有约束 + 静默失败风险
├── patterns/           # ☆ 本项目特有写法（引擎没覆盖的组合写法）—— 复杂项目才拆
└── examples/           # ☆ 本项目已有实现范例（给后续 AI 照抄）—— 复杂项目才拆
```

**为什么强制拆成 4 本、而不是一个大 `SKILL.md`**：

- `SKILL.md` **只做导航**（保持 < 100 行）。AI 每次任务只读入口 + 按需读分册，不必吞下整份约定。
- `registry.md` 是增长最快的一本（每个消息号 / handler / 面板 / 管理器都进），
  单独放才不会把入口撑爆 —— 这也是单文件方案最先崩的地方。
- `constraints.md` 独立，让"约束与风险"能持续追加而不影响其它册。

## 1. `SKILL.md`（入口 / 索引，必填）

```markdown
# <!-- 项目名 --> · 项目级 skill

> **动本项目代码前先读这里**。本目录只记**本项目特有**的东西；通用规则看全局 `clover-engine` skill，
> 引擎权威说明看 `clover-doc/`。
> ⛔ **全局 skill 的规则层（其 `SKILL.md` §0~§7）不可被本文件覆盖**：本文件只能在
> 「全局没写 / 全局明说可自选」的地方定约定（技术选型、命名、目录细分、消息号分段）。
> 凡全局标了 `⛔` / **硬规则** / **硬闸门** 的，**本文件只许加严、不许放宽**；
> 冲突时照全局做，并把本文件的冲突行改掉。完整层级见全局 `SKILL.md` §1.10。

本项目：<!-- 一句话 + 跑法 -->

## 索引

| 想找什么 | 去哪 |
| --- | --- |
| 消息号段分配、命名、目录边界 | `conventions.md` |
| 已有消息号 / handler / 面板 / 管理器 / 配表 | `registry.md` |
| 引擎/平台约束、静默失败风险、未决问题 | `constraints.md` |
| 本项目特有的写法范式 | `patterns/`（有才建） |
| 可照抄的实现范例 | `examples/`（有才建） |

## 四条硬规则

1. 新设施先登记再写代码：新增消息号 / handler / 面板 / 管理器 / 配表 → **同步更新 `registry.md`**。
2. 只记本项目特有的东西，通用规则**不许**抄进来（抄了必然两边漂移）。
3. ⛔ **本文件只许对全局 skill "加严"，不许"放宽"**：全局规则层（§0~§7）与本文件冲突时**以全局为准**，
   并**把本文件的冲突行改掉**（不是"说明一下冲突"就算完）。真觉得规则不合理 → 回报用户改 skill。
   ⛔ **特别注意这几条不许在本文件里被"项目化"放宽**：
   临时文件位置（全局 §1.8：一律 `<项目根>/.ai-tmp/`，⛔ 不许 `client/_dev/`、项目根、`tools/`）；
   交付闸门（§2）；收尾机械自检（§1.11）；引擎能力优先（§6）。
   （实测反面：项目级 skill 把探针位置写成 `client/_dev/` ⇒ 探针堆了**上百个文件**，子 agent 全照章执行。
   ⚠️ 这条反过来也成立：**新项目不许把全局规则层"本地化"成更松的版本**。）
4. **子 agent 不会自动继承 skill**：派子 agent 时，任务书里必须写明「怎么拿到本 skill」——
   首选让它读 `<项目根>/tools/ai-skill/SKILL.md`，再给全局 `clover-engine` 与 `unity-cli` 的入口路径。
   只写"先加载 skill"是不够的（很多宿主没有 `use_skill` 工具，IDE 也不解析 `skills:` 字段）。
```

## 2. `conventions.md`（本项目约定，必填）

```markdown
# 本项目约定

## 消息号段分配

| 段 | 范围 | 用途 |
| --- | --- | --- |
| 引擎 | 1 - 10000 | 引擎占用，业务不许用（硬约束：业务 C2S 必须 > 10000） |
| C2S | 1000101 起 | <!-- 本项目实际分段 --> |
| 回包 | **不占消息号** | 引擎按 requestID 配对，回包帧 msgID 恒为 0；只定义回复体结构，不定义常量 |
| 推送 | 3002001 起 | |

## 命名

- 服务端 `MsgXxx` / `onXxx`；客户端 `MsgDef.Xxx`（如 `MsgDef.Match`）/ `XxxPanel` / `XxxManager`。
- <!-- 本项目额外约定 -->

## 目录边界

- <!-- 哪些目录归谁、不许在哪儿放代码 -->

## 与全局 skill 的差异（**只许记"加严"，不许记"放宽"**）

| 项 | 全局 skill 写法 | 本项目写法 | 性质 | 原因 |
| --- | --- | --- | --- | --- |
| <!-- 例：客户端配置加载器 --> | `ClientConfig.cs` 静态类 | `ConfigLoader` MonoBehaviour 单例 | 加严 | <!-- 历史原因 --> |
| <!-- 例：单机项目 --> | 默认按形态判定 | 单机：`Game.Net` 等一律为 null 不许碰 | 加严 | 形态=单机 |
```

> 这一节是**项目级 skill 存在的最大理由** —— 历史包袱、特殊取舍都记在这，否则后续 AI 会照着通用写法"纠正"你。
> ⛔ 但**"放宽"类差异一律不许写进这张表**（形态：在全局规则层 `§0~§7` 的范围内，本表无内容可记）。
> 判据一句话：**本表每一行都必须是"比全局更严"**；出现"比全局更松"的行 ⇒ 删掉它，改照全局做。
> 若确实需要放宽（例如引擎能力在本项目真的用不上），**正确做法是登记到
> `策划/验收表.md` 的「允许的差异」小节**（带实测证据 + 何时消除，见全局 `SKILL.md` §1.11 第 4 条），
> **而不是写进项目级 skill 当约定**。

## 5. 复杂项目怎么扩（判据 + 拆法）

多 agent、多子系统时，上面 4 本会继续膨胀。**满足任一条就拆**，不要硬塞：

| 症状 | 拆法 |
| --- | --- |
| `registry.md` > 60 行 | 拆成 `server.md`（消息号 + handler + schema）/ `client.md`（面板 + 管理器）/ `tables.md`（配表） |
| `SKILL.md` > 100 行 | 继续往分册挪，入口只留索引 |
| 出现引擎写过的组合写法 | 建 `patterns/<主题>.md`，一篇一个，`SKILL.md` 登记一行 |
| 有实现值得后续照抄 | 建 `examples/<主题>.md`，并在 `SKILL.md` 写一句"照它写" |

复杂项目的完整形态：

```text
<项目根>/
├── docs/                       # 【过程】这次怎么做的 → 任务结束即冻结
│   ├── 步骤文档.md              #   总纲（见 patterns/multi-agent.md）
│   └── agents/agent-NN-*.md    #   每个 agent 的任务书
└── tools/ai-skill/             # 【结果与约定】后面的人该知道什么 → 持续更新
    ├── SKILL.md
    ├── conventions.md
    ├── registry.md             #   膨胀后拆 server.md / client.md / tables.md
    ├── constraints.md
    ├── patterns/
    └── examples/
```

**`docs/` 与 `tools/ai-skill/` 绝不许混**：

| | `docs/` | `tools/ai-skill/` |
| --- | --- | --- |
| 记什么 | **过程**：这次拆了几步、谁做哪块、当时怎么决策 | **结果**：做完之后有哪些设施、有哪些约定、有哪些约束 |
| 生命周期 | 任务结束就冻结，是**历史记录** | 持续更新，是**活文档** |
| 读者 | 复盘的人 | **下一个动代码的 AI / 人** |
